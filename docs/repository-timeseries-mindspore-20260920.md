## 验收与费用

输入为 180 条固定合成价格，测试替换 Alpha Vantage 的外部数据响应，保留原下载解析流程。默认完整流程运行 100 个 epoch，使用原始 0.2 Dropout，检查 128 个训练预测、32 个验证预测、次日预测、五幅图及真实 MindSpore 自动微分。它检验执行完整性，不是实际股票预测效果实验。

数值验收在相同源端参数和输入下关闭 Dropout，逐步比较三次连续 Adam 更新的前向值、损失、梯度向量和参数更新。种子为 101、202、303；三种子验证同一个候选，不作为三次独立转换。前向最大绝对差阈值为 1e-4，损失绝对差为 0.02，梯度向量 L2 差为 0.05，参数更新相对 L2 差为 0.03，预处理最大绝对差为 1e-9。学习率检查覆盖第 0、39、40、79、80 个零起始 epoch。源端数值由独立进程生成，参考输出不进入 agent 工作区。

公开接入要求目标提供原有模型与预处理接口，以及 `make_optimizer`、`train_batch`、`learning_rate_for_epoch` 和返回末态的 `main`。这些接口统一用于完整流程和外部测量，不提供健康目标代码或修复位置。文件覆盖检查包括全部 Python 文件及 notebook 代码单元的语法、目标框架导入；分步教学片段原本依赖前面片段的全局状态，其独立启动不作为源仓库已有能力。

每个修复条件上限为 40 次模型调用、120,000 输出 token、1,800 秒与 4 次外部提交；单次输出上限 16,384 token。所有失败调用保留。没有修改 baseline 的原生算法、解析、语义分析或重试策略。

首次整仓库初译的单次输出上限为 32,768 token，接口返回 `finish_reason=length`，32,768 token 全部用于推理，最终代码内容为空；实际调用包含 28,926 输入 token，共 61,694 token，未产生候选。原始响应和错误状态均保留。用户随后讨论是否提高推理预算或按文件转换，采用保留推理的依赖顺序生成：核心主程序、参数映射及依赖为第一阶段，上限 65,536 token；教学片段、notebook 和 README 为第二阶段，上限 32,768 token，复用前一阶段的核心实现。上限同时包含推理和最终文本，不是单独的推理预算。两个阶段之间不运行验收、不人工修复或选择候选；三种方法共享最终相同文件，并归入此前耗尽调用及两阶段调用的全部费用。验收契约和修复方法预算保持原值。

## 接入记录

实现位于独立工作树 `/media/main/whj/projects/torch4ms/ascend-torch4ms-repository-pilot-20260920`，分支为 `codex/repository-timeseries-mindspore-20260920`。起点为 `694f692`，沿用上一轮实际使用的 baseline 接入文件，包括已经核验的 SWE 进程续接与 DeepSeek 消息传输。新接入只扩展完整源／目标目录、工具路径、Git 跟踪、沙箱与公开任务描述。

MatchFix 以完整 `project.py` 模块作为源／目标对应入口，并通过工具访问全部仓库文件；其原生 `MatchAgent.run`、六个语义角色、修复与判决编排保持原样。这个仓库的完整主流程集中在单个入口模块，其他 Python 文件是该流程的教学分步片段；没有把多文件代码拼成一个伪模块。该设置沿用已有共享工具后端，不能称为未经适配的原生 CLI 实验。

源环境与目标环境分开：源端沿用此前评估环境的 NumPy 1.26.4，目标端使用继承 `mstorch` 的独立虚拟环境，MindSpore 2.7.2、NumPy 2.0.2。补装 Alpha Vantage 和 notebook 格式依赖。沙箱增加对虚拟环境所引用的 Python 基础环境的只读访问，SWE 保留虚拟环境解释器路径；这些属于依赖接入修正。

启动前，三个源端参考运行、数值验收的正负控制，以及十二项零模型接入检查通过。原有运行时相关测试首次为 80 通过、2 跳过、1 失败；失败是默认提示合同被全局替换导致的兼容性断言。随后将目标描述限定在仓库任务，原默认合同恢复，相关三项检查通过。真实模型调用使用固定后的代码，启动清单记录文件哈希。
