# 累计组件消融执行报告（2026-09-22）

8 次新增运行已全部完成。四个配置都完整修复时间序列仓库，并在双塔推荐仓库通过 131/145 个检查；每个配置的完整仓库接受数均为 1/2。最终所有声明检查都有测量值。新增组件改变了调用过程和 token 开销，本次运行的最终通过数保持一致。

## 实验设计

两个仓库分别执行四个累计配置，每格新运行一次。原始源程序、初始候选、接口要求、评估输入、初始状态、评估随机种子、阈值和完整训练信号保持一致。没有重跑旧 baseline，也没有把历史运行混入这 8 次结果。模型请求统一为 `deepseek-v4-flash`，启用 thinking 和 high reasoning effort；实际响应模型标识为 `deepseek-flash`，请求未发送 seed 或 temperature。该设计记录每格一次运行的结果。

| 配置 | 增加的组件 |
| --- | --- |
| Repair agent | 使用相同证据提示、工具、语法检查、证据压缩和进度提醒进行修复 |
| + Verifier investigation | 增加独立的只读调查阶段，修复继续使用同一对话 |
| + Independent handoff | 把调查记录作为证据交给新的修复对话 |
| + Repository context | 增加依赖计划、检查点、带版本的证据检索及上下文重建 |

每次运行的共同预算为 80 次模型调用、480,000 个输出 token、3,600 秒和最多 4 次外部提交，单次输出上限为 32,768 token。启用调查的配置最多使用 6 次调用及 64,000 个输出 token，全部计入同一生命周期预算。首次修复阶段最多 16 次调用；后续阶段按照剩余提交次数分配余量。正式调度最多三项并发。

时间序列沿用 23 个检查 × 3 个评估种子，共 69 项；双塔推荐沿用 108 个训练数值检查、6 个检索检查、24 个执行/步数/自动微分检查和 7 个源程序行为检查，共 145 项。检查数用于描述候选的完成程度，完整仓库接受仍由原协议的外部评估决定。

## 最终结果

成本采用输入与输出 token 之和。下表调用数仅含本次调查和修复；端到端 token 额外归入一次共用初始翻译的既有成本：时间序列 163,661 token（3 次历史调用），双塔推荐 368,368 token（20 次历史调用）。本次新增翻译调用为 0。

| 时间序列 | Repair agent | 69/69 | 是 | 26 | 5,964,670 | 6,128,331 | 2 |
| 双塔推荐 | Repair agent | 131/145 | 否 | 62 | 7,967,319 | 8,335,687 | 4 |

| 时间序列 | + Independent handoff | 69/69 | 是 | 26 | 5,883,413 | 6,047,074 | 2 |

时间序列配置的端到端 token 依次为 6,128,331、3,896,158、6,047,074 和 1,936,579。完整方法比基础修复配置少用 68.4%，一次提交即通过。独立 handoff 在这次运行中使用了两次被截断的模型响应，两次调用及全部 token 均计入结果。

双塔推荐四个配置的 14 个最终失败项完全相同：6 个模型变体在第 2、3 步的 item embedding 共 12 项，以及 history 变体第 1 步、position 变体第 2 步的 parameter update 共 2 项。各配置的 user embedding、loss、epoch loss 和 gradient 均为 18/18，item embedding 为 6/18，parameter update 为 16/18，原仓库 10 个测试均通过。通过部分训练数值和原测试仍留下上述迁移差异。

推荐任务的前三个配置在最后阶段达到上下文上限，分别使用 62、59 和 68 次调用。完整方法进行了 6 次上下文重建，继续运行到 80 次调用上限，最终仍为 131/145，端到端 token 为 10,191,440。这些记录表明上下文管理使后续修复得以继续，剩余调用在本次运行中没有消除相同的 14 个差异。时间序列完整方法共进行了 3 次上下文重建。

本次实际新增 361 次调用，共 52,875,757 token，其中输入 51,549,552、输出 1,326,205。未知 usage 为 0；361 个 request、response 和 metadata 一一对应。所有失败阶段、无效最终 JSON 和两次响应截断的调用均保留在账本中。部分时间序列阶段返回 `invalid_final`，该标签记录代理最终 JSON 的解析状态；对应候选随后通过外部执行评估，因此完整接受记录为通过。

每项运行都在声明的调用、输出及时间上限内启动模型请求。最多使用 80 次调用、441,774 个输出 token、2,689.87 秒；未触发 480,000 个输出 token 或 3,600 秒上限。第一轮推荐完整方法曾出现执行失败及缺测，后续提交恢复测量；所有中间状态保留在原始记录中，最终 145 项均有测量。
