## 主集合与比较方法

主实验统一为健康 PyTorch 源程序到 MindSpore 的端到端迁移。保留原来的 50 个任务编号，输入、初态、种子与最终验收对各方法一致。

| 方法 | 正式输入与执行流程 | 当前准备状态 |
| --- | --- | --- |
| LaDiM | 共同初译，自主调查、独立证据交接、修复和重试 | 当前确定的实现；真实控制器与验收器模拟接入通过 |
| Direct LLM | 从源程序直接生成共同初译，执行最终验收 | 请求已冻结；生成失败留档与禁止重复生成检查通过 |
| SWE-agent | 共同初译，原生工具、历史、提交和后续检查 | 从固定上游提交导出原版代码；原生执行与公共测试接入通过 |
| MatchFixAgent | 完整源程序与共同初译，原生分析、修复、判定编排 | 原生编排和解析器接入通过，健康目标代码字段为空 |
| MSAdapter | 原版适配库，按其方式替换 PyTorch 导入 | 上游代码无修改；实际遇到的算子失败保留 |
| CodeTransEngine，直接翻译配置 | 原生直接路径生成与接口测试，再做统一最终验收 | 已恢复干净上游；原生服务、解析、测试执行与费用记录通过 |

Direct 的候选同时作为三个修复方法的起点；每个修复方法的端到端成本包含这次初译。实际支出只记录一次物理调用。MSAdapter、CodeTransEngine 各走自己的迁移流程。

### 50 个编号与 29 组输入

50 份源程序已齐备：12 份既有原生源程序逐字保留，38 份按公开接口和行为新编写。新文件的依据与哈希已记录，没有读取隐藏健康目标来反推源程序。

核对得到 24 份不同的源代码、29 组不同的“源程序＋公开契约”。原来因故障位置不同而分开的任务，在移除故障候选并改为端到端输入后，部分输入相同。

建议批准的处理是：保留 50 个编号，完全相同的源程序、契约、初译、方法和验收条件只执行一次，再关联到对应编号。主表展示通过编号数除以 50，同时报告通过不同输入组数除以 29；统计推断按不同输入组处理，不把别名当作独立试验。三个验收种子也不增加任务分母。

这样主表有 300 个单元格，实际为 174 个不同方法条件：29 次 Direct 初译、29 次 CodeTransEngine 迁移、29 次 MSAdapter 转换和 87 个修复条件。这是待审查的复用方案，尚未据此启动实验。

四个原适配层接口任务需要显式对应到原生行为：两个任务检查可训练参数枚举与梯度赋值，另两个任务检查按给定学习率构造优化器并排除冻结参数。函数签名保留，原生行为在公开契约中说明。这些属于新定义的源程序任务，不称为历史原文件恢复。

全部对应关系见 [源程序登记表](../data/benchmarks/unified50_20260918/manifest.json)；逐方法对应关系见 [主实验矩阵](../data/audits/unified50-preflight-20260918/final_review/matrix.json)。

## 验收与信息可见范围

公开内容包括完整源程序、行为契约、当前候选和实际测试观测。模型不接收故障类别真值、注入位置、健康目标实现、历史修复答案或其他方法的运行轨迹。分类与定位来自 agent 自己的调查。调查阶段只能写临时测试，不能修改生产代码。

共同验收使用种子 101、202、303。源端与目标端使用相同输入，按参数名称和形状显式对齐初始值。三次全部通过才接受一个候选。形状与数据类型精确匹配；浮点前向值采用绝对及相对容差各 0.0001，梯度为 0.0001 与 0.001，更新为 0.00001 与 0.001；BF16 矩阵乘法的绝对容差为 0.01。初始参数与可训练标记精确匹配。

检查范围按源程序公开语义预先确定：算子任务测量输出和适用的输入梯度；模型任务测量输出和适用的参数梯度；含训练入口的任务另外执行连续两步训练并测量参数更新；参数与优化器接口任务检查其声明的枚举、赋值或更新行为。辅助数据生成函数不是逐个独立认证的对象。没有参数的算子不产生虚构的更新指标。

目标后端检查记录实际张量类型、梯度引擎与训练执行证据。候选通过现有隔离执行器运行，源端数值轨迹和健康校准目标不放入可见工作区。异常后的未测数值保留为缺失，失败不移出分母。

所有修复方法均可通过公共测试获取同样的完整测量和错误。控制器不根据已知故障类别选择修复路径。
