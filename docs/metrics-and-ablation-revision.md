## 主表指标

| 指标 | 定义和作用 | 当前可用数据 |
| --- | --- | --- |
| Accepted repairs | 在各面板注明的预算内，接受数 / 独立实例数；直接回答修复效果 | MindSpore 四次尝试；JAX 的预算单独注明 |
| First-attempt acceptance | 第一次尝试被接受的实例数 / 全部实例数；衡量首次修复质量 | 两个框架均有 |
| Tokens per accepted repair | 所有实例全部尝试的输入和输出 token 总数 / 接受数；包括失败成本 | 两个框架均有；零接受时为 n/a |
| Seconds per accepted repair | 所有实例记录的耗时总和 / 接受数；包括失败成本 | 两个框架均有；零接受时为 n/a |

MindSpore 的接受规则是原实验针对注入故障的检查。JAX 的接受规则是三个种子上的
训练验证。表中按框架分组、注明口径，不计算跨框架合并成功率。
顺序修复中的第 1/2/4 次尝试检查点沿用“在预算内接受”，不改称独立采样的 pass@k。
耗时取已记录运行时间，包含 API 延迟等运行条件；这里没有新做计时实验。

原表中的 Execution、Forward values、Gradients and parameter updates 是按注入故障
类别分组的修复接受数。它们不能直接改名为“执行通过率、前向一致率、梯度一致率”。
原始主实验部分方法没有记录这些逐阶段最终状态。定位准确率 48/50 和检测延迟来自
单独的诊断实验，保留在诊断分析中。

未来若补充逐阶段最终验证，可报告完整训练验证通过率和分阶段通过率。执行失败后的
前向、梯度、更新测量记为 n/a，并同时给出执行失败数量及各指标分母。测试覆盖率需要
单独的覆盖率测量；当前日志不能填。BLEU、CodeBLEU、代码行数和总尝试次数不加入
当前主表：前两者不能直接反映训练语义，后两者也不能替代修复正确性与成本。

## 已核对的论文指标

联网核对日期：2026-09-16。以下名称以原论文为准；不同论文里的 CA 缩写含义不同。

| 论文及原文位置 | 实际指标 | 本文采用的启示 |
| --- | --- | --- |
| [MatchFixAgent](https://arxiv.org/html/2509.16187v1)，§4.2、Table 2 | EQ、NEQ、Validation Failure；能给出等价性判断的比例、与已有工具的一致率；平均判断耗时及美元成本 | 把验证覆盖、判断一致性与修复成功率分开 |
| 同文 §4.3、Table 3 | 修复成功数/率，以原有测试中原来失败的测试全部通过为准；还报告代码覆盖率 | 主表使用明确验收规则下的接受数和成功率 |
| 同文 §4.5、Table 5 | 消融中的判定准确性、交互轮数、输入 token、输出 token、耗时 | 报告 token 和时间，注明成本分母与运行口径 |
| [InterTrans](https://arxiv.org/html/2411.01063v1#S3.SS4)，§3.4 | Computational Accuracy：通过执行测试、对相同输入产生相同输出的翻译比例；直接翻译基线区分 CA@1 与 CA@10 | 以执行行为正确性为主要结果，注明尝试预算 |
| [ExeCoder](https://aclanthology.org/2025.emnlp-main.362/)，[PDF](https://aclanthology.org/2025.emnlp-main.362.pdf) §4.1、Table 1 | Compilation Accuracy（CA）、Case Computational Accuracy（CCA）、Test Computational Accuracy（TCA）；另有 EM、BLEU、CodeBLEU | 将编译、测试用例、完整测试通过率区分；本文进一步关心训练中的梯度和参数更新 |

MatchFixAgent 的 99.2% 指能给出判断的覆盖比例，72.8% 是与对照工具的一致比例。
其 §4.3 的 134/265 = 50.6% 是在双方都生成补丁的比较集合上的修复率。
这些数值都不是本论文 MindSpore 基线的 47/50。§4.5 的“准确性”以两个系统一致的
1,091 个非争议案例作为参考集合，也应按该定义理解。

## 方法组件与当前消融

按机制分成四部分：多种验证信号、首个失败阶段定位、针对性修复指导、修复过程控制。
最后一部分包括反馈历史和回滚两个可单独关闭的行为。Direct LLM 保留为主表中的
系统级对照，本轮不新增独立的多智能体消融。

| Experiment J 设置 | 给修复 LLM 的信息 | 对应接受数 |
| --- | --- | --- |
| Execution only | 执行状态、异常和 traceback；正常执行的数值故障不触发修复 | 33/50 |
| Pass/fail only | 完整验证后只给一个总通过/失败位 | 34/50 |
| Stage label only | 只给首个失败阶段标签，隐藏具体数值、张量和参数细节 | 34/50 |
| Flat full feedback | 提供全部测量，不指定首个失败阶段或对应的修复路由 | 34/50 |
| LaDiM | 全部测量、首个失败阶段、针对性指导 | 第三轮 48/50 |
| Reverse presentation | 保持同样的诊断和修复路由，倒转报告的文字顺序 | 第三轮 48/50 |

Stage label only 只暴露阶段标签。原契约的 `hierarchical_routing=true` 在此条件下
没有提供数值/参数诊断。保留完整测量及阶段选择、只去掉修复指导的控制仍待测量。

Experiment J 的主表来源为
`data/experiments/10_experiment_J_feedback_ablation/formal_run_2d6bd3d/summary.csv`
及对应 JSON。前四行来自初次评估，后两行来自第三轮确认；Pass/fail 行从
`1ef4691` 导入，其余采用 `2d6bd3d`。所有行使用四次尝试、temperature 0 和
paired-threshold 验证，不能填入原始 temperature 0.1、故障特定验收的主实验结果。
论文表注注明 LaDiM 使用第三次独立运行，附录列出全部三轮：LaDiM 44/47/48，
反序 49/46/48，分母均为 50。内部实验编号、归档过程与提交版本保留在本说明和数据来源文件中。

这些数据支持完整诊断和指导的组合：三个 LaDiM 运行都高于 flat 的 34/50。
它们没有单独分离阶段选择与指导的贡献。两种报告顺序没有稳定的胜负，反序实验
测的是信息呈现顺序，不能当作“关闭分层诊断”的消融。

12 任务的 4/12、8/12、12/12 单列为信号覆盖表：分别使用执行；执行加前向；
执行加前向、梯度和参数更新。每个阶段四个任务，扩大信号范围后才能触发对应故障的修复。
这解释信号覆盖，不替代组件控制。已删去将 flat 设置的表现概括为方法“little help”的句子。

## 已留空的结果和补测优先级

| 优先级 | 留空控制 | 保持固定 | 单独改变 |
| --- | --- | --- | --- |
| 1 | Without targeted guidance | 完整测量、首个失败阶段、修复历史和回滚 | 删除该阶段的具体修复建议 |
| 2 | Without repair history | 当前诊断、指导、回滚及预算 | 隐藏前次编辑与结果，保留当前程序状态 |
| 3 | Without rollback | 当前诊断、指导、历史及预算 | 每次保留最新补丁，不按验证分数回滚 |

论文用 -- 留出上述结果，尚未给它们虚构分母或成功率。若要进一步单独量化阶段选择，
需要在完整证据下交叉设计“有/无阶段选择 × 有/无针对性指导”；明确无阶段选择时
指导如何生成后，再加入该控制。现有 flat 同时取消了阶段选择和指导。

补测可先固定一个 16–24 实例的分层子集，覆盖执行、前向、梯度、参数更新，兼顾
模型和修复位置。所有新控制及完整 LaDiM 都跑同一批实例、同一预算和验收规则；
已有的 50 实例汇总不能直接充当这个小子集的对照。选样应在查看新控制结果前固定。
小差距需要更多重复或实例才能判断，子集规模不保证一定能得到清楚的趋势。

## JAX 样本规模

现有 6 个实例可以在主表独立面板中展示跨框架结果。一个实例相当于 16.7 个百分点，
5/6 与 6/6 的差距只有一个实例。三个验证种子仍属于同一实例，分母保持 6。

若希望 JAX 承担更强的比较结论，建议下一轮目标为约 18–24 个独立实例。这是工作量
与覆盖面的设计建议，不是统计上的合格线。优先增加不同故障实现和模型组合，分别覆盖
梯度错误和参数更新错误；条件允许时增加 Transformer 类模型或兼容层修复位置。
所有比较方法使用同一实例清单，提前固定尝试预算和验收规则。

## 消融表的论文呈现

对照用户提供的 MatchFixAgent PDF 第 3.4 节及 Figure 4，以及 ExeCoder 的 Tables 2–7，
消融围绕组件变化比较效果和成本。MatchFixAgent 关闭语义分析器，报告判定准确性、
输入/输出 token、交互轮数和耗时；ExeCoder 比较单独加入语义、语法、数据流信息和
逐步加入各训练阶段的变体，报告不同翻译方向的编译、用例和完整测试通过率。
本地 MatchFixAgent PDF 的章节编号为 3.4；上文联网查阅的 v1 对应第 4.5 节。

论文主消融表以变体为行，结果为列：接受数、首次接受率、每次接受修复的 token 和秒数。
变体定义放在正文，反序呈现及重复运行结果放在附录。表中没有组件开关列。
未测的三个控制仍以 -- 保留。表题与正文不使用内部实验编号、提交哈希或归档汇总名称。
正文分析完整诊断怎样影响修复效果和成本，来源映射由生成脚本和本文件记录。
