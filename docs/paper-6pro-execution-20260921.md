## 5. 需要新实验的设计

### 5.1 LD → IEH → DCM 的累加消融

用同一冻结源码、初始翻译、评估输入、预算、完整训练信号和工具集，比较四个条件：基础修复代理；加入 LD；继续加入 IEH；再加入 DCM，得到完整 LaDiM。基础条件保留通用读写与测试能力，三个组件按定义逐项启用。将进度提醒和编辑格式辅助固定为相同设置。

两个仓库各做四个条件、三次独立 agent 运行，共 24 次。按现有每仓库最多 80 次诊断/修复调用计算，上限为 1,920 次调用；这是设计上限，未执行。初始翻译固定并按原口径计入总成本。评估种子沿用原协议，独立 agent 运行和评估种子分开记录。

自然翻译的十个程序先比较前三个条件，观察初始错误程序修复和初始正确程序保留。现有逐项移除结果继续作为原有证据保留，不重排成未执行过的累加结果。

### 5.2 DCM 内部组件

在固定 LD、IEH、工具和预算的条件下，依次加入依赖检查点、可检索证据归档、事件触发的上下文重建。记录最终验收、相同文件哈希的重复读取、相同候选版本的重复测试、归档检索、上下文重建和调用成本，检验证据保留与失效机制分别影响什么行为。

### 5.3 相同信号下的组织方式

固定 IEH 和完整训练观测，比较平铺提供观测与按训练依赖组织观测。该实验检验组织方式，与现有“加入哪种信号”的覆盖消融分别回答不同问题。

### 5.4 首次检测与定位成本

分别记录首次检测的训练步、首次检测 token、首次有证据支持的定位 token、最终修复 token。首次检测事件以证据通过工具返回并可供代理使用的时刻为准。定位事件还需对应代码位置或区分性测试证据。初始反馈已给出故障的情况单独标记；预算内没有出现事件的任务保留为未检测或未定位。

先核对已有 trace 能否对齐工具事件、候选哈希、时间戳和 usage。记录足够时可以离线重建；缺少对齐信息时，需要为所有方法补上相同日志后运行匹配实验。本轮没有开展这项 trace 重建或新增运行。

各新实验统一报告 1、2、4 次提交时的验收、错误程序修复、正确程序保留、行为检查通过数、调用次数、输入/输出/总 token，并保留失败成本和声明分母。
