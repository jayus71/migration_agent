## 论文的研究问题与主要主张

本文研究如何让迁移后的深度学习程序保持源程序的训练行为。程序能够执行、当前输出接近之后，反向计算和优化器更新仍可能存在偏差；这些偏差会改变后续训练。对于 agent，困难还包括从测试观测中提出故障假设，找到值得检查的代码，并根据修改后的测量继续调查。论文围绕这些困难解释 LaDiM 的设计和效果。

主张明确表述为：LaDiM 利用分层训练观测自主调查并修复迁移偏差，在统一 MindSpore 迁移实验中达到与 MatchFixAgent 相同的完整验收覆盖，并减少 57.4% 的端到端 tokens；跨语言迁移和 JAX 修复结果进一步展示了 LaDiM 在不同语言与目标框架中的有效性。训练信号实验解释为何前向值、梯度和参数更新能为这一过程提供互补证据。

LaDiM 将执行、前向值、梯度和参数更新作为调查依据。独立 Verifier 读取程序并运行测试，自主建立观测与可能故障位置之间的联系；Repair Agent 接收调查证据，继续检查和修改候选，外部验收决定是否完成迁移。这样的叙述让训练行为、调查过程和最终结果连在一起，也与当前实现中自由调查、证据交接及重试的流程一致。

Translator 保留在完整框架中，在方法概览用一至两句交代其输入和初始候选输出，框架图中保留入口节点。方法小节标题和贡献条目围绕训练观测、自主诊断和修复展开。共同初译为后续调查与修复提供相同起点，其生成成本纳入完整迁移过程。

跨语言实验扩展的是这个研究问题的适用环境。源程序与目标程序的语言和框架都可能变化，而需要核查的对象仍是对应的训练计算。方法先定义这些共同对象，再说明各运行环境如何提供观测，跨语言结果就能直接检验同一调查与修复机制。

正文直接陈述上述贡献、结果和科学含义。每项主张依据实际设计和测量确定，实验条件集中放在设置中。组织段落时围绕读者理解方法所需的信息展开，删除围绕假想审稿意见设置的反面观点、防御性否认和重复降调。措辞调整应使贡献更清楚，事实、数字及必要条件保持准确。

## 方法章节的具体论证

### 概览：交代完整流程

开篇说明 LaDiM 接收源程序、目标环境和公开训练契约，返回目标候选及验收状态。Translator 生成初始候选，Verifier 调查代码与训练观测，Repair Agent 使用调查证据修改程序，控制器执行检查并反馈未解决的差异。概览段到这里即可，随后直接进入训练行为的定义。

框架图与该段保持一致，呈现候选、证据和测试反馈的流向。Verifier 指负责调查的模型角色，验收控制器负责执行既定检查和判断是否通过；成文时保持二者称谓一致。已有候选也可从调查阶段接入，用于补充的候选修复研究。

### 2.1 Task Definition and Training Observations

这一节先定义源程序与目标程序各自的语言和框架，以及需要保留的训练行为。公开契约给出输入、初始状态、对应张量、适用计算和接受条件，允许修改的范围决定修复工作区。PyTorch 到 MindSpore 与 Java/DJL 到 Python/PyTorch 是这一任务定义下的两个设置。用简洁的定义把它们纳入同一个问题后，后文即可共用诊断与修复描述。

随后解释执行接口如何使观测具有可比性。源端和目标端使用对应输入、初始值与参数身份，返回执行结果、前向值、梯度和参数更新，并按任务契约提供缓冲区或优化器状态。可以保留一个观测集合公式说明比较对象；执行失败时记录异常和已经取得的观测，其他项保留缺失状态。诊断摘要帮助 agent 检查差异，验收采用契约规定的完整比较。具体数值阈值进入实验设置。

这部分需要解释观测各自提供的信息：前向值描述当前计算，梯度反映反向传播，参数更新反映优化器对状态的作用；这些计算之间的依赖决定了差异可能怎样传播。跨语言执行接口负责将对应计算呈现为可比较的观测。共同入口、参数映射和训练状态的保存属于实现这些比较的条件，在这里说明用途，在实验设置说明实际执行步骤。

该节结束时，读者应理解“如何观察迁移差异”，从而自然进入“如何调查差异的来源”。逐步同步和连续状态演化是具体研究的不同执行条件，分别在对应实验中定义。

### 2.2 Autonomous Layered Diagnosis

这一节从训练阶段的关系展开诊断思路。执行异常提供异常信息和相关代码线索；前向偏差可能影响后续梯度与更新；前向观测一致而梯度异常时，求导路径和参数参与情况值得检查；梯度一致而更新异常时，优化器及其状态成为调查对象。这些关系提供形成和检验假设的依据，故障位置由进一步检查确定。

接着具体说明 agent 的调查动作。Verifier 读取源程序、目标候选、公开契约和相关库实现，自主选择文件搜索、已有测试与临时测试。它将测量结果同代码事实联系起来，提出可能的机制与位置，再设计能够区分这些解释的检查。例如，观察到对应参数的梯度缺失后，可以检查其求导参与情况，并用局部测试确认。这个例子用于解释调查逻辑；若成文引用实际案例，应从已有轨迹中对应观测、检查和补丁，保留真实过程。

“分层”在本文中指训练观测及其计算依赖。当前证据模式让 agent 自主调查，控制器提供公开任务、代码和测试反馈；报告中的故障描述及代码位置由调查形成。论文据此介绍分层诊断，调查路径、补充测试和位置判断均按 agent 的实际行为描述。

最后解释调查产物如何供修复使用：记录已观察的事实、可能原因、相关代码位置及未解决问题，并保留支撑这些判断的工具观测。读者需要看清每个候选修复位置为什么值得检查，以及后续测试怎样支持或推翻假设。假设记录按实际生成情况介绍，过程说明使用调查轨迹，效果评价使用最终验收。

这几段构成方法的主要技术内容，重点展开观测、假设、代码检查和补充测试之间的联系。角色与工具的定义服务于这条信息流。

### 2.3 Evidence-Guided Repair

这一节首先解释独立调查与修复之间的信息交接。Verifier 在调查期间保持生产代码只读，使报告对应当前候选的实际状态。Repair Agent 在独立会话中接收调查记录及工具观测，可以检查假设、继续运行测试，并修改允许编辑的代码。这样的设计使修复获得明确的调查起点，角色分工和交接内容构成可复现的方法描述。

随后说明一次修改怎样进入后续循环。编辑经过语法检查并保存在工作区；提交后，控制器运行验收，将测量差异返回修复会话。Repair Agent 结合初始调查、当前代码和新的结果决定下一步，已有修复上下文按配置保留。初次独立调查之后，后续修复阶段继续使用工具开展调查。图和正文都应与这个调用顺序一致。

结束段给出完成条件：候选满足规定检查及确认要求时返回接受结果，预算耗尽时返回当前候选和验收状态。原本正确的候选也能在调查与确认后完成流程。预算提醒、编辑事务和上下文管理按实际行为简洁交代，组件实验在后文讨论这些配置的表现。

方法章节由此形成一条完整的信息链：契约确定比较对象，执行取得训练观测，自主调查建立假设与位置，证据交接支持编辑，验收结果推动下一步。语言和运行时变化影响候选及执行接口，调查与修复的组织方式保持一致。

## 实验章节的具体论证

### 3.1 Experimental Setup

设置集中说明任务、比较方法、验收和成本，后续结果段直接引用这些定义。主表使用两个面板，分别对应 50 个 PyTorch 到 MindSpore 任务标识与 18 个 Java/DJL 到 Python/PyTorch 任务；每个面板内方法共享适用的任务输入和最终验收。前者的 50 个标识对应 29 个不同源程序与契约组合、24 个源文件，完全相同条件只执行一次，token 计入实际调用。这个映射在设置中说明一次，摘要和主表继续报告 50/50。

框架迁移比较 LaDiM、MatchFixAgent、SWE-agent、Direct LLM、CodeTransEngine 和 MSAdapter；跨语言比较前三个 agent、Direct LLM、InterTrans 和普通测试修复。说明共同初译及各方法原生输入的接入方式，保留原生工具、提示和重试行为，所有模型调用使用同一 DeepSeek 后端。初译与后续调查修复的调用一起构成端到端成本。

验收说明涵盖输入、初始状态、随机种子、阈值和适用计算。跨语言研究比较预处理后连续两步的输出、损失、梯度、参数更新与可观测优化器状态，源端和目标端各自保存步骤间的训练状态。可见检查与确认检查按实际协议说明。调用数、输出预算、时间、外部提交次数，以及失败和未完成执行的计分与成本在此统一定义；方法内部调用与外部提交分别计量。

### 3.2 Main Experiments

主实验首先回答 LaDiM 能否在统一验收下完成迁移，以及达到该结果的模型使用。框架迁移段以 LaDiM 和 MatchFixAgent 均为 50/50、LaDiM 少用 57.4% tokens 为中心，结合共同初译的 29/50 说明调查与修复带来的覆盖增加。完整方法结果留在主表，正文解释已正确候选的保持和剩余故障的修复怎样组成最终结果。

跨语言段检验相同训练调查机制在语言和框架同时变化时的效果。LaDiM 将共同初译的 1/18 提高到 9/18，SWE-agent 与 MatchFixAgent 均为 8/18，普通测试修复为 7/18。LaDiM 通过的程序包括一个应用程序和全部八个教材示例，新增覆盖集中在教材示例。其 tokens 比 SWE-agent 和 MatchFixAgent 分别少 11.7% 和 24.2%，在所测方向上同时取得较高覆盖和较低 agent 成本。

这两段承担整套方法的有效性与效率结论。跨语言结果直接放在主实验，与主表第二个面板相邻。两个面板各保留其任务与分母，读者可以分别判断两种迁移条件下的表现。

### 3.3 Analysis Experiments

“Repair Behavior and Token Use” 解释成本优势在什么输入和处理阶段出现。图 3(a)给出总量，图 3(b)给出对应输入的成本；LaDiM 在 29 个不同输入组合中的 27 个使用更少 tokens，其中包含九个初始故障组合中的八个。故障组合的额外调查与修复成本为 3.32 百万和 6.53 百万 tokens，节省 49.2%。这一分解将整体效率结论落实到确实需要修改程序的任务，同时说明正确候选的确认也是迁移成本的一部分。

同一小节随后解释重试的作用。LaDiM 在一、二、四次外部提交预算下分别通过 46/50、50/50 和 50/50；两个不同故障组合在第二次提交后完成修复。MatchFixAgent 在第一次外部提交内通过全部任务，其内部分析与修复包含多次模型调用。这组观察用于分析调用组织和后续修复，成本比较采用累计调用及 tokens。

“Training Signals and Detection Latency” 回应引言中的训练故障动机。梯度和更新检查在各自 12 次运行中都于第 1 步发现故障，平均损失差异分别到第 31、18 步越过阈值，观察窗口内个体损失轨迹分别有 3/12、4/12 次越阈。正文解释直接训练信号为何能更早提供调查线索，图注清楚区分均值曲线与个体检测时间。

“Generalization Across Frameworks” 保留既定标题，用六个 JAX 给定候选修复任务说明执行接口变化后的适用性。LaDiM 与共享工具的直接修复对照均通过 6/6，段落重点说明如何通过 TorchAX、JAX 和 Optax 取得对应观测并完成修复。成本和完整配置保留在现有补充材料。该研究承担另一目标框架上的应用证据，跨语言端到端效果由主实验承担。

### 3.4 Ablation Studies

训练信号消融回答可见验证信号怎样影响完整调查与修复流程。四个模型分别包含执行、前向、梯度和更新故障，四种反馈条件各有 16 个实例；所有最终候选都用完整检查评分。随着默认反馈逐步加入前向值、梯度和更新，最终通过数依次为 4/16、8/16、12/16 和 16/16。分析围绕遗漏故障怎样被暴露、何时触发修复以及什么条件使流程结束展开，未触发修复数为这些过程提供直接证据。

证据交接和修复上下文作为第二部分，用一个完整段落概括组件对照。独立交接与连续对话分别为 50/50 和 49/50；移除历史或提醒仍通过 50/50，并使用更少 tokens。多数输入在确认或一次纠正后完成，后续尝试较少，这为上下文配置的成本差异提供了具体背景。正文据此讨论交互选择的表现，完整组件矩阵保留在附录，包含各项已测结果。

信号研究和 JAX 研究沿用其已记录的编辑示例、格式反馈及任务协议，主比较使用当前冻结方法；这些实现差异在补充协议中明确列出。主结果、行为分析和消融各使用对应实验的定义与证据。
