## A. 完整程序到原生 JAX 的迁移比较（推荐）

科学问题是：LaDiM 的完整翻译、调查和修复流程，在目标端采用原生 JAX 自动微分和 Optax 更新时，能否保持训练行为，并取得怎样的验收覆盖和 token 成本。现有 TorchAX 六例保留原实验身份；新结果作为完整源程序迁移研究。

采用已核对的四个真实模型定义：`PaperCnn`、`TinyImageMLP`、`TinyTransformerClassifier`、`TinyCausalLM`。模型来源沿用训练信号实验的合法 PyTorch 源定义，排除故障注入代码和任何健康目标实现。每个模型分别定义 SGD 与 Adam 训练契约，共 8 个迁移配置、4 个模型源定义。两个优化器条件属于同一模型的配对配置，按模型分组分析。

源端训练驱动在准备阶段单独编写并冻结，显式保留模型、参数、缓冲区和优化器状态。现有信号脚本的 `train_one_step` 每次新建 SGD，不能直接用作具有持续 Adam 状态的新协议。预定 SGD 学习率 0.01、无动量；Adam 学习率 0.001，`betas=(0.9, 0.999)`、`eps=1e-8`、无权重衰减。数值配对采用关闭 Dropout 的确定性配置；原生随机训练能否执行单独记录。

| 比较方法 | 输入和运行方式 | 新增条件 |
| --- | --- | ---: |
| Direct LLM | 每个配置从完整 PyTorch 源程序生成一次原生 JAX 初译 | 8 次初译 |
| LaDiM | 从该配置的共同初译开始，使用当前主方法的调查与修复流程 | 8 个修复条件 |
| SWE-agent | 相同源程序、初译和契约，保留原生控制与工具 | 8 个修复条件 |
| MatchFixAgent | 相同源程序、初译和契约，保留原生分析、修复和判决编排 | 8 个修复条件 |

四种方法在同一张比较表中报告结果。Direct 的终态就是共同初译；其他方法的端到端费用均包含该初译，实际支出只计一次。初译若在预算内未产生可执行候选，按预先规定的失败产物交接规则处理并计入分母，禁止挑选更好的第二份初译。规则需在付费请求前完成模拟验证。

目标产物使用 JAX/Flax/Optax。模型前向、梯度和更新都必须由目标运行时实际执行，参数及优化器状态通过明确接口传入并返回。原生 JAX 的状态处理需要对应的执行接入；现有 TorchAX runner 可复用隔离和账本部分，不能原样承担这一验收。[JAX 状态计算文档](https://docs.jax.dev/en/latest/stateful-computations.html)、[TorchAX 项目说明](https://github.com/google/torchax)

公开反馈检查连续 3 步，公共种子 101，最终确认种子 202 和 303。同一候选通过三个种子才接受，三个种子不增加迁移样本数。统一比较前向值、损失、参数梯度、参数更新、适用的优化器状态，以及参数形状、类型和可训练属性。拟沿用主实验的前向绝对/相对容差 `1e-4/1e-4`、梯度 `1e-4/1e-3`、更新 `1e-5/1e-3`；优化器状态需预先确定对应关系及逐字段容差。阈值在无模型调用的正负控制后冻结，正式比较中保持一致。

准备阶段完成四模型源检查、目标测量接口、参数与状态映射、源目标初始化对齐、正负控制、目标运行证明以及三个 agent 的假传输接入检查。模型角色、工具提示和重试保留当前冻结方法，只修改目标运行时和输入契约所必需的接入。baseline 的算法、提示、解析器及内部重试保持上游设定。

主要指标为 8 个配置的完整验收数、初译失败后的修复数、初译已通过的保持数、端到端 token、调用数和耗时。记录 1、2、4 次外部提交时的当前候选状态。每模型两项优化器结果同时展示，失败结果保留在完整矩阵中。

论文位置为 `Generalization Across Frameworks`。建议用一个紧凑的四方法结果面板和两段分析，分别解释新增覆盖及不同模型/优化器中的修复行为，预计增加约 0.4–0.5 页。详细程序、状态映射和逐任务结果放附录。

## B. 修复产物的连续训练验证（推荐，无新增 LLM 调用）

科学问题是：在短程训练检查后提交的最终程序，继续独立训练时，其前向、梯度与更新如何随步数变化。直接执行冻结的初译和最终候选，新增计算用于评估训练行为。

现有统一集合中，按源程序公开 `train_step` 接口选择全部 7 个不同训练配置：`group_019`、`group_020`、`group_021`、`group_022`、`group_023`、`group_024`、`group_027`。选择依据是任务接口，覆盖六个主表方法的全部终态，最多 42 份方法产物、126 条三种子配对轨迹。原来仅有算子或参数枚举接口的任务维持各自验收范围。部分源程序有共享结构，按源程序哈希保留分组关系。

再将 A 的 8 个 JAX 配置与四方法终态全部纳入相同的延长评估，共增加最多 96 条三种子配对轨迹。两组最多 222 条配对轨迹，分别汇报；实际执行失败后的数值标记为 `n/a`。若 A 尚未完成，先完成现有 MindSpore 产物的 126 条上限矩阵。

每条轨迹最长 100 步，固定种子 101、202、303 与批次序列。仅在起点对齐源目标状态，随后双方保留各自训练状态。原源程序若在步骤之间重建优化器，也保持这一原行为；A 中声明持续优化器状态的程序则持续保存。记录每步的损失、梯度与更新误差，并在第 1、2、5、10、20、50、100 步汇报。更新差异和累计参数差异分别保存。

另用独立的每步同步观测定位误差来源：将目标置于相应源状态后测量单步计算。这条辅助轨迹与连续训练轨迹分开运行和统计，用来解释单步计算偏差与累积状态偏差。优先完整保存连续轨迹，再根据异常位置补同步观测，避免对所有产物重复执行整条辅助轨迹。

原主表继续使用原短程协议，新增结果报告连续训练轨迹及长程检查的通过情况。原有阈值保持原值；新增累计参数指标只报告测量量，若要设置新的接受界限，须在查看候选长程结果前冻结。遇到漂移保留整条轨迹，本轮评估不对终态再做修复。

准备阶段重点核对持续状态、输入序列、随机计算和测量器开销。历史 Torch4MS 真实规模实验曾出现训练漂移；本次使用当前原生 MindSpore 主表产物，运行目录和后端均与该历史研究分开。连续训练结果由实际测量确定。

论文位置为 `Analysis Experiments`，接在检测延迟分析之后。新增一张两面板小图，区分连续训练误差与同步单步误差，配一至两段机制分析，预计增加约 0.35–0.45 页。现有图 1 保留检测问题，新增图回答最终迁移程序的训练行为。

## D. 仓库迁移（后续独立研究）

当前时间序列案例已经完成主脚本、notebook 和教学片段的运行扩展，但方法间可见反馈不同；双塔案例包含运行中获批提高预算的续接，三方法最终都未通过完整验收；Simple MoE 试点在生产文件产生修改前耗尽预算。这些记录适合确定仓库方法的开发问题。

## 预算、服务器与执行顺序

| 项目 | 新增模型条件 | 模型调用上限 | 输出 token 上限 | 预计总 token |
| --- | ---: | ---: | ---: | ---: |
| A | 8 次初译 + 24 个修复条件 | 968 | 3,928,576 | 约 1,000–2,500 万 |
| B | 0 | 0 | 0 | 0 |
| C（可选） | 8 个修复条件 | 320 | 960,000 | 约 200–600 万 |
| 推荐 A+B | 同 A | 968 | 3,928,576 | 约 1,000–2,500 万 |
| A+B+C | 8 次初译 + 32 个修复条件 | 1,288 | 4,888,576 | 约 1,200–3,100 万 |

每个初译条件最多一次请求，输出上限 131,072；每个修复条件最多 40 次调用、120,000 输出 token、1,800 秒、4 次外部提交，每调用输出上限 16,384。LaDiM 调查和修复每阶段最多 8 次调用。推理和最终内容都计入输出额度。模型沿用主实验请求配置 `deepseek-v4-flash`、温度 0、推理开启、强度 high，保存服务方实际返回的模型标识。

预计总 token 包含输入与输出，是规划估算。A 的基准按既有 MindSpore 三 agent 的实际总量剔除共享初译重复归属后，折算 8 个配置约为 1,027 万 token；原生 JAX 接入和更完整模型可能增加调查量，因此预留至 2,500 万。C 参考既有连续会话开销并扩大范围。表中硬上限约束调用与输出，累计输入按实际使用留账；预计总 token 不能当作费用硬封顶。人民币费用须使用当前接口账单中的缓存命中、未命中和输出单价，本轮未请求计费接口。
