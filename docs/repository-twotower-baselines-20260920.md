# 双塔仓库：扩大输出上限后的方法对照

SWE-agent 和 MatchFixAgent 已按用户要求并行运行完毕。两者都在第 40 次调用后停止，未通过完整迁移验收。LaDiM 的现有候选也未通过：它完成了原测试及文件迁移，MatchFix 完成了训练 CLI，当前结果体现不同部分的完成情况。

## 共同任务和预算

源为 `gauravchak/two_tower_models`，提交 `cf86221775efec3184e83b9417bf9daeddc4e057`。两组目标目录最初均为同一冻结 PyTorch 源码的完整副本，没有使用 LaDiM 已生成或修复的文件。各方法需要自行完成原生 MindSpore 转换，并满足同一源输入、初始状态、随机种子、接口和最终验收。

每组上限为 40 次模型调用、240,000 输出 token、1,800 秒和 4 次外部提交；每次最多 32,768 输出 token，包含推理和最终内容。两组从第一条请求即采用此配置。模型保持 `deepseek-v4-flash`，响应回报 `deepseek-flash`，推理开启、强度 high。没有额外生成费用、隐藏重试或用量重置。

LaDiM 的现有结果来自先用较低单次上限、再经用户授权提高额度的续接；其累计调用、输出上限和最终验收与本次对照一致，但预算分配过程经过开发调整。下表是一个仓库的开发对照，尚不是从同一预先冻结配置开展的重复实验。

原测试因收集期间仍导入 PyTorch 而没有进入测试函数执行，不记为零个测试通过或数值零差异。三个方法均未通过公共种子的完整验收，因此没有执行额外两个种子的确认。两个排序扩展在源端本身存在异常或空实现，不计为已完成的排序算法。

LaDiM 已完成六条源端可执行路径的推理和三步训练，10 个原测试及其断言保持情况也已核对。但 CLI 仍把 `lr` 传给 MindSpore Adam；训练等价还存在表示、梯度和更新差异。其修改了 19 个文件，不因文件覆盖较完整就记作迁移成功。

SWE-agent 最终修改了最大内积检索模块和历史编码器，共 2 个生产文件。基础模型、训练器和测试仍保留源框架导入，阻止数值与入口执行。其 40 个模型请求均来自原生 SWE 会话，最终状态为调用预算耗尽。

MatchFixAgent 修改了 10 个模型模块和训练入口，共 11 个生产文件。训练 CLI 实际完成一轮、16 个样本、2 次原生 `value_and_grad` 调用，梯度有限性检查通过。数值测量在缺少 `parameter_map.json` 时停止，原测试、README 和依赖文件尚未迁移。没有替其补写参数映射或修改测试。

这些结果表明，当前 LaDiM 在测试与交付文件覆盖上推进得更完整，MatchFix 在独立训练入口上完成了 LaDiM 尚未完成的一步。三种方法在该仓库的完整成功数均为 0；当前结果不支持完整成功率优势。LaDiM 的总 token 也略高于两个 baseline，尚无成本领先证据。

## 费用与停止原因

| 方法 | 调用 | 输出 token | 输入 token | 缓存命中输入 | 缓存未命中输入 | 输入缓存命中率 | 运行秒数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| LaDiM（含原运行） | 33 | 240,000 | 3,284,695 | 3,062,912 | 221,783 | 93.25% | 975.42 |
| SWE-agent | 40 | 50,812 | 3,221,736 | 3,105,024 | 116,712 | 96.38% | 335.64 |
| MatchFixAgent | 40 | 73,637 | 3,227,210 | 3,066,880 | 160,330 | 95.03% | 347.75 |

两个 baseline 合计新增 80 次调用、6,573,395 总 token。全部请求有响应，用量与控制器记录一致；没有 API 错误、未知用量或输出截断。其输出使用量分别只占 240,000 上限的 21.17% 和 30.68%，实际约束是 40 次调用。LaDiM 则先触及累计输出上限。对这两条 baseline 轨迹，只提高单次输出额度没有消除调查与多次工具交互造成的调用消耗。

保留各方法原有消息和会话组织，没有新增提示前缀重写或证据压缩机制。MatchFix 仍按原生角色重新组织各次会话，SWE 仍执行原生历史处理；实际缓存命中量如表所示。费用以完整输入、输出及缓存用量记录，未依据未知渠道单价换算货币。

## 实现与接入审计

SWE 使用固定的 1.1.0 上游提交 `0f3acafacabc0def8cc76b4e48acb4b6cf302cb9`，保留原生 shell、编辑器、解析器、提交和历史处理。MatchFix 使用上游提交 `66a52a5626f5e8b480abbcd4b0e7a287fb3d85a7` 的完整 `MatchAgent.run`，六个语义角色、修复与判决编排保持原样；原生静态图分支不必产生模型请求。后端沿用既有共享工具适配，不能将其描述为原作者 Claude/Codex CLI 的直接运行。此次预算在修复角色内耗尽，没有为判决另加额度。

MatchFix 的源／目标入口为真实的 `source/train/train.py` 和 `target/train/train.py`，并可通过工具访问其余完整仓库；健康目标字段为空。任务只增加这两个路由字段，科学验收合同与原双塔任务逐项一致。初始目标是未翻译的源码副本，本次评价的是这些原生编排在该端到端任务设置中的表现。

准备阶段发现既有 SWE 接入把目标入口固定为时间序列案例的 `target/project.py`。在独立运行时副本中，将该文件存在性检查改为读取任务声明的 `target_entry`，保留路径和只读保护。这是评估接入修正；上游算法、提示、解析器和重试策略未修改。此前 LaDiM 和时间序列运行所用文件保持字节不变，差异记录在 `preparation.json`。

12 项零模型接入检查通过，包括源与初始目标一致、完整公开测试可用、源和任务只读、MatchFix 配对、SWE 原生进程初始化及未翻译候选确实被原生目标验收拒绝。结束后，两组各 13 项完整性核验、隔离运行时哈希以及原运行时哈希全部通过。

本轮没有修复 baseline 的候选或功能失败，也没有修改论文或重跑 LaDiM。观察到的调查成本和文件遗漏保留为后续审查自身调度的依据。
