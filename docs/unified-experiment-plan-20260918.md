## 建议采用的组织方式

固定现有 50 个任务作为主集合，补齐健康 PyTorch 源程序，用于端到端迁移比较。每个任务另保留原来的故障候选，承接已完成修复实验的分析。主实验与分析引用同一任务登记表，分别记录输入和运行流程；新增插拔实验优先复用主实验的共同初译及原生宿主运行。

跨框架和跨语言实验保留，分别回答目标框架变化、程序语言变化后方法是否仍然有效。每组内部固定任务集合、输入、最终验收和分母。它们不合并进主实验的 50 例，也不再因方法不同各自挑选子集。

正文建议使用一张主比较表、一张包含跨框架与跨语言分区的泛化表，以及一张消融表。修复过程、预算收益、错误分布与插拔作用优先通过共享图或相应表中的分区表达。表的组织服从研究问题，已有批次不各占一张表。

## 主集合的准备与验收

每个任务保存完整健康源程序、公开行为契约、评估输入、初始状态、适用的测量字段、最终检查及原故障候选。编号沿用现有 50 例。12 份已编写的原生 PyTorch 源程序保留；其余 38 份按公开接口和任务行为编写，其中 4 例需要明确适配层接口与原生 PyTorch 行为的对应关系。新文件记录作者、依据、时间和哈希，不作为恢复出的历史原文件。

源程序编写以公开任务行为和原生接口为依据，不读取隐藏健康目标来反推源代码，也不把故障位置或修复说明写入源程序注释。没有充分说明的行为先写成明确契约，再审阅源程序与任务含义的一致性。源程序不根据哪个方法能通过来调整。已有私有探针与新契约发生分歧时，保留原实验记录，并在新协议冻结前解决分歧。

现有 50 例包含算子、训练流程及适配层接口。必测项按任务语义预先确定：输出、类型、形状、有限性、适用的梯度以及训练任务中的参数更新。同一任务对所有方法采用完全相同的必测项。目标执行路径另行记录，避免把 PyTorch 回退计为 MindSpore 迁移完成。没有参数的算子不虚构参数更新结果。

主指标为通过全部必测项的任务数除以 50。输入、初始参数、种子、阈值和检查字段在运行前冻结；多个种子是同一候选的验收条件，不增加任务数。执行异常后的未测数值记为不可用。后续可以统一扩展验收输入，但应保留旧评分与新评分的区别。

这 50 个任务已经参与框架开发和版本选择，报告时保留这一事实，不把它们称为未参与开发的测试集。跨框架和完整跨语言源程序的结果用于补充适用范围证据，是否未参与调参按各自历史记录判断。

主方法、SWE-agent 与 MatchFixAgent 使用同一个完整初译候选。共享初译在方法级端到端成本中各计一次，在实际支出账本中仅记录真实发生的调用。MSAdapter 与 CodeTransEngine 走各自原生迁移流程。Direct 为直接生成控制。InterTrans 在 PyTorch 到 MindSpore 方向的适用性尚未确认，现有 Java 到 Python 结果仅进入跨语言比较。

所有 LLM 使用已配置的 DeepSeek。外部方法保留原生算法、工具、提示、内部历史与重试逻辑；公共评估层统一任务、可用参考和资源上限。资源上限及超限状态在正式矩阵冻结前声明。接口适配与环境依赖可修正，baseline 自身算法失败保留。

## 跨框架实验如何处理

JAX 六例目前有可用的修复证据：自主流程与 Direct 都是 6/6，Direct 成本更低。自主流程使用带编辑格式辅助的实现，当前选定实现去掉了该辅助。因此这些记录能保留原配置下的泛化结论；若要把结果明确归到当前选定实现，先检查冻结代码和请求，再决定是否仅新增当前方法的六个条件。Direct 的六条有效结果不随主方法变化重新生成。

推荐先保留现有六例和实际配置，完成离线实现核对。本轮不将这六例扩成 50 例，也不自动重跑当前方法。论文对实际实现差异采用功能描述，内部版本名只留在证据记录。

Ivy 与 torch2jax 的现有 0/6 来自已有故障的输入，测量转换是否消除了那些故障。它们不能作为健康源程序到 JAX 的迁移成功率。若确需端到端转换器比较，应使用同一健康 PyTorch 源程序，按两者的原生流程离线转换和验收，并与相同入口的方法比较；已有健康检查材料先核对复用。这部分不消耗 DeepSeek 调用。

跨框架表报告任务数、最终通过、实际目标后端与成本。只在同一任务和流程分区内横向比较。主文不把修复 6/6 与健康源迁移 0/6 放成同一排名。

## 插拔实验和消融实验如何处理

插拔实验继续用主集合的 50 个任务及主实验的共同初译，不另建数据集。推荐保留两个宿主的三种条件：原生流程、原生流程加完整公共测量、原生流程加自主调查证据。这样能区分“提供更多测量”与“对证据进行调查和组织”的作用。原生宿主条件优先直接使用主实验记录；初译已正确的任务仍保留在分母中，另记健康保留。调查调用与宿主调用共用总预算。自主调查过程不得直接编辑生产文件，否则检验的就不再只是诊断证据的作用。

旧插拔实现含规则分类、预选位置和按故障选择的源片段，不能直接替换名称后当作自主调查结果。新的普通宿主条件与已完成运行完全一致时复用；其余条件在统一源程序和输入冻结后列入可选择的补跑范围，不自动启动旧 300 条矩阵。若先做一个宿主，应按预先指定的宿主完成全部 50 例，并说明这是缩小后的研究范围。

组件消融优先复用已完成的同一 50 例记录，保留它们原有共同对照。现有其他组件条件以带编辑格式辅助的实现为参照；当前方法是在这个参照上去掉格式辅助得到的。直接用当前方法的 45/50 替换旧参照的 41/50，会让部分比较同时变化两个因素。现有结果可作为组件研究和方法选择依据，不能改写成当前最终配置的逐项消融。

若正文需要最终配置的严格单因素消融，应在统一任务协议上只列确实缺失的条件。已完成的 16 例训练信号实验可独立保留，说明前向值、梯度和更新检查对修复触发与停止的作用，无需仅为统一版本标签再跑 64 条。
