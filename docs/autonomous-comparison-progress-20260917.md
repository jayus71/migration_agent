原 50 例的主指标是四次尝试内通过该实例原有故障探针的比例，分母固定为 50，并报告第 1、2、4 次尝试的累计接受数。这适合衡量受控故障修复。去除答案后仍沿用这些探针，分类和定位不参与控制器选路，由 agent 自行调查并另行评分。

“配对验收”把源框架与目标框架的程序置于相同初态和输入，比较实际前向值、梯度和参数更新。它用于独立的十例自然迁移实验；本轮不把这一更强标准加入原 50 例的主指标，也不将两类分母混合。

本轮自然任务的实际执行方式是 MindSpore 前向与求导，再经 torch4ms 的 `Torch4msOptimizer` 转换梯度并调用原生 PyTorch 优化器完成更新。后端观察器确认被测模型及损失对应的 MindSpore 梯度；参数更新表确认数值一致，不证明更新 kernel 属于 MindSpore。这个优化器路径来自冻结原始输入，各方法沿用同一设置。结果按这一混合执行范围解释。

旧 50 例的接受数为我们 50、MatchFix 47、SWE 46、Direct 40；这些数值来自带有类别、定位或答案提示的旧输入，不能替代本轮自主诊断实验。旧稿约 29 倍 token 优势还涉及成本漏计：原始调用中我们使用 589,239 token，旧汇总报告 190,588；保留旧成功数重算，该比值约 9.40。详细依据见 [baseline-implementation-audit-20260917.md](baseline-implementation-audit-20260917.md)。新统计计入所有实际请求，包括失败调用；缺失 usage 显式标记，零成功时每次成功成本为 n/a。

真实 SWE-agent 接入固定上游 1.1.0 的 DefaultAgent、原生 shell、编辑器、parser、历史处理和 submit review，不施加八次调用的阶段切片。脚本模型集成已验证跨提交历史和公共验收桥接；隔离检查覆盖原生所有 I/O、网络、信号、终端和真实 MindSpore 求导。

MatchFix 完整编排接入每轮重新执行上游 `MatchAgent.run` 的六个语义组件、TestGenRepair 和 Verdict；底层编码后端适配同一模型及真实文件工具，明确记录该适配。原 50 例没有真实源/目标程序对，MatchFix 在这组任务标记不适用，不把健康答案伪装成源程序，也不把不适用计成失败。它在自然十例中参与完整流程比较。

后续冻结配置沿用服务器当前请求模型 `deepseek-v4-flash`，并记录实际回复名；thinking enabled、high effort，单次最多 16,384 输出 token，每实例最多 40 次调用、120,000 输出 token、1,800 秒和四次外部提交。客户端统一上限为 1,000,000 字符，它是保守的本地容量限制，不等同于 provider 的 token 窗口。我们的方法分别保留证据压缩及原始历史消融；baseline 使用自己的历史机制。正式执行以运行目录的最终 manifest 为准。

按用户后续讨论，主方法移除强制类别输出。Verifier 交付真实观测、位置、原因假设、支持或反驳的证据及剩余不确定性，修复流程不读取类别选路。另设相同预算和证据压缩配置的类别要求消融，保留原先自由文本类别输出；这两个条件只比较分类要求带来的差异。分类表仅用于评估方后验整理。

自身框架加入两项通用流程改进：多文件补丁在落盘前统一检查 Python 语法，失败则整次修改不应用并返回真实报错位置；修复阶段若提前输出总结却未编辑，或编辑后未执行测试，会在该阶段剩余预算内继续。阶段末仍未编辑、未复验分别记为 `investigation_only`、`unvalidated_repair`，外部验收照常执行，仍计入四次尝试，不增加隐含机会。

原 50 例属于源码加黑盒单元测量的修复任务。部分私有判定没有完整公开功能规格，例如返回 shape、冻结意图、残差与旋转公式；机制可能无法从单一差值唯一确定。新输入不从健康实现反推提示来补齐这些答案。部分原谓词只检验非零更新或映射集合，接受结果按“原单元检查接受”报告。两个故障的 A/B 活动探针完全相同，仍保留原 50 例分母及这一依赖关系。完整训练行为由自然迁移实验另行核对。
