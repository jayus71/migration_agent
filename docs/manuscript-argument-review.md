## 核对依据

- 写作使用仓库的 humanizer 规则及 [Zhekai Du 写作 DNA](../literature/zhekai-du/Academic-Writing-DNA.md)，并核对本地 CGDM、DAMP 选段。LOMA→MOST 的比较以用户提供的意见为依据，本轮未声称核对未提供的原稿。
- [ExeCoder 的 ACL 摘要](https://aclanthology.org/2025.emnlp-main.362/)描述可执行性表示，不应写成仅用执行反馈的修复 agent。
- [RepoTransAgent §III-A、§III-D](https://arxiv.org/html/2508.17720v1)利用检索上下文、测试错误和反思进行修改。
- [MatchFixAgent §3.1–3.4](https://arxiv.org/html/2509.16187v1)将多方面语义分析报告交给测试与修复 agent，再由 verdict agent 汇总；它的反馈不能概括为只有 pass/fail。
- 已核对本地 SWE-agent、AutoGen 原文。多 agent 的角色分工与训练阶段诊断是两个设计维度。
- 实现核对 `ascend-torch4ms/autofix/orchestrator.py` 及 `autofix/agents/`：三个 agent，由编排器传递诊断、检查修改效果、保留改善和回退未改善修改。
- 读取 `README.md`、`data/paper_figures/README.md`、原 Fixed50 摘要，以及 Experiment C、K 的来源说明；用于保持诊断与修复证据的区分，不据旧交接说明改写冻结的数值。
