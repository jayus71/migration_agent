# 工作单元规划消融

本轮只新增时间序列和推荐仓库各一次关闭工作单元规划的运行。完整方法复用已完成的自动映射消融中的两项 full 结果，没有重新调用模型运行完整方法。复用前逐项核对源程序、共同初译、任务、参考执行材料、评估代码中的种子与阈值、模型配置、调用和输出预算及冻结核心实现；56 项离线检查和五项逐运行复用检查全部通过。

## 消融边界

本轮移除显式工作单元计划，以及依赖该计划才能执行的规则：`plan_units`、`focus_unit`、`checkpoint_unit` 三个工具；前置单位检查点就绪门控；聚焦单位限定的生产文件编辑边界；上游单位修改引起的依赖检查点传播；切换单位触发的上下文整理。它测量工作单元规划在当前实现中的整体作用，包含上述执行规则。只删除 plan 工具会导致生产文件无法获得合法活动单位，从而阻断全部生产编辑。

自动文件、符号、import 和 notebook 单元映射保持不变。普通公开读取、搜索、合法目标文件编辑、语法保护、运行测试、notebook 单元编辑事务、独立调查与角色交接、版本化证据、容量触发的上下文整理均保留。无活动单位时，原有工作集函数自然保留全仓库最近已读且文件哈希仍匹配的内容，沿用同一 120,000 字符上限。源文件和 task 仍不可编辑，评估材料仍在候选工作区之外。

适配器为 `experiments/work_unit_planning_ablation_20260922/unit_adapter.py`，未修改共同核心实现。编辑事务复制冻结的原方法，仅删除活动单位门控和依赖检查点传播，并直接调用其原 WorkspaceTools 事务层，保留 notebook 检查、原子编辑、语法校验、内容版本与测试过期处理。测试将变换后的抽象语法树与冻结原函数逐项比较，防止附带修改。

## 验证与协议

20 项机制测试通过，其中包含八项专门消融测试与十二项原工具测试。测试覆盖无计划的跨文件编辑、完整方法仍执行原路径约束、源/task/调查阶段只读、自动映射完全一致、三个规划工具不可调用、notebook 事务回滚、全仓库工作集、测试证据过期、独立交接提示以及原容量整理不重置费用。

各新增运行最多 80 次模型调用、480,000 输出 token、3,600 秒和四次外部提交，单次输出上限 32,768。调查阶段最多六次调用、64,000 输出 token；首次修复最多 16 次调用，后续阶段按剩余提交次数分配余量。模型请求为 `deepseek-v4-flash`，沿用 thinking/high reasoning effort，不新增 temperature 或模型 seed。评估随机种子与阈值由冻结输入和评估代码确定。

主指标是完整仓库接受状态。时间序列 69 项、推荐 145 项检查仅描述同一候选的完成程度，缺测始终单列。提交时的累计调用、token、通过与未测项目，以及实际 map/read/edit/test 轨迹作为过程证据。复用的完整方法费用不计入本轮新增 API 支出，端到端比较仍分别归入一次共同初译费用。

为避免与正在执行的 JAX 实验争用，本轮单 worker 串行运行，固定 CPU 4、5，OMP/BLAS 线程数为一；已有完整方法使用原来的非绑定 CPU 位置。该资源放置差异保留在 `reuse_consistency.json` 中，调用、输出和时间上限均不变。各格一次观察，尚未估计模型运行间变动。
