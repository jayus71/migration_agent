## Layered Diagnosis 的实际依据

冻结代理以执行结果、前向值、梯度和参数更新等公开观测开展调查。角色指令要求提出机制假设，以代码位置和观察结果支持结论，并设计能够区分或反驳假设的测试；失败修复后的新旧测量用于选择后续探查。

`output/maintext-ablations-20260918/frozen_v4_agent.py:27` 的 `SYSTEM_PROMPT` 及 `:101` 的 `_evidence_prompt()` 支持上述行为。后者移除了强制类别输出，保留 observations、locations、evidence 和 hypotheses。冻结实现没有将四类差异写成确定性的 `if/else` 分类器，也没有规定每次必须按四阶段依次调用工具。`experiments/unified_migration50_20260918/domain.py:7` 仅调整源/目标框架名称，没有加入另一套分层路由。

因此，论文保留训练计算依赖对调查方向的解释：执行错误支持检查异常调用，前向差异支持检查产生数值的运算，前向一致时的梯度差异支持检查注册和微分路径，前向和梯度一致时的更新差异支持检查优化器。具体工具与探查顺序由 LLM 根据角色指令、当前观测和已取得证据选择。算法没有增加实现中不存在的类别标签、路由器或定位答案。

## 单程序与仓库入口的区别

主统一比较的调用链是 `experiments/unified_migration50_20260918/integration.py:37` → 注入当前 evaluator → `experiment.run_condition()`。本地冻结控制器副本 `output/maintext-ablations-20260918/autonomous/experiment.py:159–195` 的顺序是：初始配对测量 → 独立调查 → 再次配对测量 → 公共检查通过后确认 → 如仍未接受，进入修复。每次修复后重新测量，并在公共检查通过时确认。

仓库 `scripts/repository_migration_experiment.py:307–345` 的顺序是：初始 `ev.final()` → 已接受则返回 → 否则调查 → 直接进入修复 → 每次提交后调用 `ev.final()`。调查结束与第一次修复之间复用已有观测，没有额外的仓库验证调用。

为保持这一差异，算法 2 现在接收 `E` 和已知状态 `q`，接口为 `Repair(T,S,E,q,M,B,C)`。它不再负责初始测量、调用调查或诊断后的初始确认，只保留提交后的验证。单程序入口顺序写在 3.3 正文；算法 3 在初始仓库验证失败后调用 `LayeredDiagnosis`，将原观测、调查证据和状态直接传给 `Repair`。原稿通过算法 2 复用而多出一次仓库验证的问题已消除。未引入运行实现中没有的验证缓存。
