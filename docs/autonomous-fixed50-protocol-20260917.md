# Fixed50 自主诊断与定位评估协议

本协议使用原 Fixed50 的 50 个初态和四次修复预算，评估模型在没有预设类别、责任文件、修复提示和健康目标实现时，能否依据公开代码与真实测试结果提出诊断、定位问题并恢复原单元测试契约。类别字段可选，不影响评分、工具权限、验收或重试。后验分析可以整理故障类型；类别要求本身的作用由同一框架有无该要求的消融检验。

本文件及配套 [私有评分表](../data/audits/fixed50-private-diagnosis-rubric-20260917.json) 包含故障映射和健康／故障差异，仅供评估端使用。二者不得进入 agent 工作区、检索目录、系统提示、用户提示、工具输出或修复历史。私有评分表保存 50 个匿名任务的初态观察、输入哈希、原验收脚本哈希、注入位置和差异；这些材料用于审阅结果，不参与 agent 的推理流程。

## 数据和验收来源

原任务池固定到实验仓库提交 `3454be4e1e58f4889e362bd33289d49f98ebbcf6`，从 `experiments/paper_section_65_66/run_section65_real_fault_repair.py` 的 `FAULT_MODEL_PAIRS` 与 `MODEL_VARIANTS` 读取原绑定。保留 25 个历史故障各两个实例，不改变分母、输入初态或四次修复预算。历史标签只保留在评估端。原提示链审计见 [25 类目录与提示来源](fault-taxonomy-and-diagnosis-audit-20260917.md)，历史结果的验收含义见 [图表数据来源](../data/paper_figures/README.md)。

服务器准备目录为 `/media/main/whj/projects/torch4ms/ascend-torch4ms-autonomous-verifier-20260917/experiments/autonomous_fixed50_20260917/preflight_v2`。原探针和隔离后的探针分别检验每个健康／故障版本：50 个健康版本全部通过，50 个故障版本全部失败，100 对判定一致；50 个任务均为 `ready`。这些是数据准备与验收一致性检查，不是 LLM 修复结果。

每个公开任务有 45 个文件：`candidate.py`、`task.json` 和完整的 43 个生产库文件。所有方法可编辑 `candidate.py` 与 `torch4ms/**/*.py`，也可创建自己的 scratch test。`task.json` 提供统一单元修复说明、模型变体和公开测试接口；不指定当前故障类别或责任路径。该任务池没有独立的原始迁移源程序，`source_reference` 为 null。健康目标和私有 Reference 实现均不作为 `source.py` 提供。实验对象因此是受控故障代码及黑盒测试反馈下的修复；完整自然迁移任务另用 Experiment I 的十例初态评估。

准备器保留全部生产实现，移除私有 Reference、探针与手工比较流程。EX-05 的故障原来位于探针的 batch 构造语句；为保留这个缺陷，所有 execution fixture 的该构造统一迁移为公开的 `input_batch()`，私有探针调用它。健康和故障导出的私有探针逐字一致。库内故障的私有探针直接导入 `torch4ms`，不额外导入公开 reproducer，以保留原入口并避免增加测试前 monkeypatch 通道。

## 实际失败与历史标签

下表按最终观察器对初态的真实反馈统计。后验阶段是评估字段，agent 无需输出这些名称。

| 初态可观测失败 | 原实例 | 数量 |
| --- | --- | ---: |
| 执行抛出异常 | EX-01–08、EX-10、NU-07 的 A/B | 20 |
| 执行完成，数值或有限性检查失败 | NU-01–06 的 A/B | 12 |
| 执行完成，输出形状契约失败 | EX-09 的 A/B | 2 |
| 梯度、参数更新、可训练性或参数选择单元失败 | GR-01–08 的 A/B | 16 |

NU-07 当前先在矩阵乘法处触发 head 维度广播异常。初态尚未测得该路径上的前向数值差异；“执行阻断／head 形状不匹配”是有效判断。EX-09 能执行并返回形状 `[4]`，私有谓词要求标量；“输出协议／形状不符合测试”是有效判断，不能要求模型报告执行异常。GR-07 测得的是优化器选入两个参数、其 `requires_grad` 为 `[false, true]`；该探针没有观测一次完整训练的梯度或更新误差。

执行失败后的未测数值、梯度和更新均为不可用。`finite=false` 是有效观测，其对应的非有限差值在反馈中为 null。缺测、零值和通过是三种不同状态。

## 公开信息的可评分范围

评分区分“私有注入机制已知”和“公开信息足以判定该机制”。冻结规则把 EX-09、NU-01、NU-04、NU-06、GR-04、GR-06 的 A/B 共 12 例标为 `contract_dependent`。它们保留在全部 50 例的检测、证据、修复接受和成本统计中；主要精确机制与责任符号定位指标使用其余 38 例。12 例单列私有参考一致性及不确定性处理，不把猜中未公开意图解释为一般诊断能力。这个划分在查看本批首次诊断轨迹前确定，不按哪个方法修复成功调整。

| 实例组 | 公开证据及可评分判断 | 具体信息缺口 |
| --- | --- | --- |
| EX-01、EX-10 | 消费者报类型或容器错误；公开生产者与消费者可共同支持返回边界定位 | 修复可发生在保持语义的任一边界，不能只按注入行判定 |
| EX-02、EX-03、EX-04、EX-07、EX-08 | dtype、排列长度、索引类型、BF16 支持或转置 rank 异常可直接核对 | 异常栈中的包装／物化位置不一定是最初责任位置；需读实际计算路径 |
| EX-05 | `input_batch()` 返回 list，消费者按字符串索引；生产者—消费者不匹配可检查 | 支持一般协议修复，不要求复述私有参考字面值 |
| EX-06 | 初始仅有 `TypeError`，消息和生产栈为空 | 私有类型断言的提示被移除；需自行运行公开 ReLU workload，检查返回类型与派发转换边界。记 `requires_own_probe`，不能仅从初始异常确定精确位置 |
| EX-09 | `[4]` 输出及测试失败可观察；重载分支可检查 | 公开说明未明确标量返回要求；选择全局均值的意图属于未公开契约 |
| NU-01、NU-04、NU-06 | 真实输出差异与相关函数可检查，模型可提出待验证假设 | 残差公式、mask 的精确填充约定、RoPE 旋转约定没有独立公开规格；单个差值／范数不足以唯一还原私有公式 |
| NU-02 | `finite=false`，公开代码有大 logits 的直接 exp/sum；可用极值输入验证溢出 | 不把仅看到非有限值视为已经定位具体算式 |
| NU-03、NU-05 | 实际 SDPA 输出差异；公开标准算子接口和实现支持局部 PyTorch 对照测试 | 初始标量差只证明不一致；mask 或缩放根因需结合源码与区分性输入 |
| NU-07 | head 维度矩阵乘法异常；公开 GQA 实现的扩展次序可检查 | 观察到执行阻断后，尚不能宣称所有后续 GQA 数值语义已经验证 |
| GR-01 | 参数仍可训练、上游梯度缺失，公开 forward 存在 detach | 可提出并用 scratch test 检验计算图中断 |
| GR-02、GR-03 | 手工流程有更新，`train_step` 全零；两个故障的初始测量可相同 | 区分清梯度次序和漏 step 需阅读控制流，不能从同一组数值直接区分 |
| GR-04、GR-06 | `fc2` 被冻结且没有梯度／更新，冻结语句公开 | 是否应训练 `fc2` 缺少独立公开任务规格；冻结是可见状态，称其“错误”依赖预期训练策略 |
| GR-05 | 首个可训练参数缺梯度、冻结参数无梯度；提取与写回路径公开 | 需检查两处参数顺序的一致性；该探针使用模拟梯度，不证明完整后端反向 |
| GR-07 | 实际选入数量与 trainability 列表公开，参数选择实现和已有注释可读 | 私有硬编码的期望数量不公开；应诊断筛选契约，不能声称观测了训练更新失败 |
| GR-08 | `fc2` 可训练且有梯度，却无参数更新；优化器参数集合公开 | 参数名是症状，机制定位需关联具体优化器构造与遗漏集合 |

`contract_dependent` 任务中，正确指出已观测异常并说明剩余语义不确定性可以获得证据评价。审阅者不能根据私有健康 diff 把这种不确定性判为错误。若 agent 的公开工具结果支持更具体的机制，单列其证据等级和与私有参考的一致性；主要 38 例分母仍冻结。新增公开规格或更强验收属于后续协议版本，应对所有方法统一重测。

## 原验收谓词覆盖的层级

以下谓词来自上述固定提交的原探针。新运行保持它们及原阈值，故结果名称使用“原故障特定单元验收”。

| 实例组 | 原谓词检验的内容 |
| --- | --- |
| EX-01、EX-10 | 下游消费正常完成，计算出的范数／和大于零 |
| EX-02 | 输出有限、形状为 `(2, 3)`、dtype 为 float32 |
| EX-03 | 输出形状为 `(8, 3, 5)` |
| EX-04、EX-05 | 索引计算值大于零；mapping 消费结果为 6.0 |
| EX-06 | ReLU 返回对象是 `torch.Tensor` |
| EX-07 | BF16 embedding 输出有限，和 PyTorch 输出的最大绝对差不超过 0.01 |
| EX-08、NU-03、NU-05、NU-07 | SDPA 输出有限，和 PyTorch 输出的最大绝对差不超过 1e-4 |
| EX-09 | 输出 rank 为零 |
| NU-01、NU-04、NU-06 | 输出有限，与私有 Reference 的最大绝对差不超过 1e-6 |
| NU-02 | 概率输出有限，各行和与 1 的最大差不超过 1e-6 |
| GR-01 | `fc1.weight` 梯度范数大于 1e-8 |
| GR-02、GR-03 | `train_step` 至少一个参数的更新范数大于 1e-8 |
| GR-04、GR-06 | `fc2.weight` 可训练，其梯度与手工流程更新范数均大于 1e-8 |
| GR-05 | 提取的可训练参数名称及顺序与预期一致；冻结参数无梯度，首个可训练参数有梯度，探针内部无异常 |
| GR-07 | 在给定一个冻结、一个可训练参数时，只选择正确的可训练参数，探针内部无异常 |
| GR-08 | `fc2.weight` 有非零梯度且手工流程产生非零更新，均大于 1e-8 |

这些谓词覆盖的性质不同。EX-03 仅检查形状，GR-02/03 只要求至少一个参数更新；GR-05 用模拟梯度和临时转换 hook，GR-07 临时替换参数转换。相应通过结果只能支持已测单元契约。完整逐参数梯度、更新向量、训练轨迹和所有输入上的语义等价性须另有测量。若最终补丁利用了弱谓词，仍保留原验收记录，并另记 `acceptance_semantic_discrepancy` 供分析，不能悄悄改写该批接受数。

候选与私有探针在同一 Python 进程中执行。Landlock/seccomp 和工具范围限制已检查普通文件／网络访问边界；此设置没有证明能抵御任意恶意候选的进程内反射、全局状态篡改或输出伪造。若轨迹实际出现这些行为，记录测试干预及其影响，不把受干预的返回值当作可信语义修复。

## A/B 的活动 probe 重复

NU-04 A/B 的实际 probe 都重置 seed 6613，使用同一 `(2, 3, 4)` scores 和相同 keep mask；NU-06 A/B 都重置 seed 6619，使用同一 `(2, 3, 6)` 输入与相同角度。各组对应的活动私有函数、活动候选函数 AST 哈希和初态观测均完全相同。模型变体改变了同一文件中的其他模型代码，没有改变这两组的实际被测 workload。配套 JSON 的 `activity_duplicates` 保存核对哈希。

主表仍保留原 50 例分母。涉及跨模型覆盖或不确定性估计时，应披露这两组已确认重复，不把每个 A/B 自动当成独立模型运行证据。若做辅助聚合，可对这两组各赋一个组权重，并同时报告原 50 例结果；已确认重复之外的活动 probe 独立性没有在本协议中全部审定。

## 首次生产编辑前的冻结与盲审

主要诊断记录冻结在首次实际生产源码字节变化之前。允许此前读取、搜索、运行原测试和编辑／运行 scratch tests。保存这一时点前最后一份显式诊断及全部此前工具证据，并保留从首个假设到最终诊断的修正记录。第一次补丁后的新发现另行记录，不回填首次编辑前判断。

原生 baseline 没有统一诊断 JSON 时，从冻结点前已明确表达的自然语言理由提取相同语义字段，不额外补问模型，也不强制增加原流程之外的调用。只有补丁而没有明示诊断时记 `not_reported`；补丁路径单独作为行为记录，不能反推其先前知道原因。无效 patch 解析且未改变生产文件不触发冻结；文件内容哈希或编辑事件证明实际变化。日志缺失导致冻结点不可恢复时记 `missing_artifact`，不当作模型判断错误。

审阅材料隐藏方法名、最终接受结果和后续补丁，只显示冻结诊断、公开初态与此前工具结果。审阅者先按公开证据评估诊断，再对照本协议的私有参考。每项判断保留原文、文件／工具证据指针、理由和审阅时间。可发表的人工准确率需独立审阅与分歧裁决；单个实施者据已知注入做的检查应标为未盲审探索性复核。

## 评分字段与位置判定

| 项目 | 评分标准 |
| --- | --- |
| 失败证据 | 正确描述实际失败、缺测或不确定性，引用确实存在的运行结果；全 50 例评价 |
| 证据有效性 | 引用内容与结论一致，源码、行号／符号、工具结果可核对；不引用未来补丁结果或私有答案 |
| 可检验机制 | 说明具体运算、协议或控制流如何产生当前现象，并提出能区分竞争解释的检查；仅关键词清单不给机制命中 |
| 责任位置 top-1/top-3 | 指出与已支持机制有关的函数、注册／转换边界或调用关系；首选位置及前三个位置分别评分 |
| 机制证据等级 | `observed_failure`：确认现象；`supported_mechanism`：公开代码路径与真实观测相互支持；`counterfactually_validated`：首次生产编辑前的隔离实验区分了该机制 |
| 不确定性处理 | 证据不足时保留竞争假设、说明缺少的规格或提出区分性实验；合理保留未知不按错误类别处理 |
| 可选类别 | 原文留存，供后验描述及分类要求消融；不列入必须字段、不因缺失扣分 |

逐项使用 `correct / partial / incorrect / undetermined / not_reported / not_scorable`。`undetermined` 表示模型显式保留未知，`not_reported` 表示没有报告该项，`not_scorable` 表示评估材料或公开契约不足以给出该项正确性判断。基础设施失败另记 `missing_artifact` 或 `not_invoked`。主要精确机制与责任位置统计报告 38 例中的各状态数量及 `correct/38`；另列 12 例的参考一致性。证据统计和单元验收始终列出全部 50 例；partial 不暗中折算为半分。

位置匹配以因果边界为单位。私有健康／故障 diff 确认原注入位置，但不要求合法修复必须编辑该行、该文件或采用健康版本的具体写法。修改生产者、消费者或适配边界，只要保留公开接口与预期语义、并有可核对证据说明能消除故障，都可成为有效责任位置。新出现的等价方案按同一规则审定，记录理由，统一应用于所有方法。

仅说“修改 `candidate.py`”或偶中 `ops/mtorch.py` 不算机制定位；这类宽泛文件命中可单列为 `file_overlap`，不进入主要责任符号准确率。只给受影响参数名属于症状位置；把异常最后一个包装／物化栈帧当根因也需独立依据。GR-05 涉及参数提取和写回两处：准确发现其中一处可记 partial，说明二者共用的可训练参数索引契约才算完整机制。

排名优先采用模型明确给出的顺序；无显式排名时，按首次明确陈述的、带有因果理由的位置取 top-1，最多取前三个。一个因果假设必须同时包含生产者与消费者时视为一个边界假设，避免因合法跨文件解释占用两个名额。大段候选清单只列出偶中的文件不获分。若模型提出未知并继续调查，按实际证据与不确定性处理评分，不生成缺失类别错误。

每条评分记录至少包含匿名任务、方法匿名键、公开输入哈希、冻结点、诊断及工具证据指针、原文机制、排名位置、可选类别、上述各项状态、证据等级、规格充分性、私有参考一致性、评语与审阅者。最终 patch 是否接受、次数及 token／时间单独关联，禁止用接受结果替代诊断评分。
