# 自动仓库映射消融：冻结设计与运行记录

四项新运行已完成。完整方法与关闭自动结构映射的条件都接受时间序列仓库，并在推荐仓库通过 131/145 项而未满足完整验收。完整映射在时间序列节省调用和 token，在推荐中较早达到最终检查水平、但最终 token 更多。本轮支持调查与修复过程存在差异，尚不支持自动映射具有普遍的接受率或费用优势。

本轮两个条件均保留工作单元规划，测量自动映射在现有规划、证据与上下文机制之上的增量作用。时间序列和双塔推荐各运行一对新实验，共四项；历史结果不参与本轮配对。每格一次运行，重复间变动尚未测量。

## 实现与归因

`scripts/repository_agent_mode.py` 中的 `inventory()` 从公开源程序和候选程序提取文件、Python 顶层符号与方法、import、notebook 单元类型与行数，附上代理自行提出的 work-unit 图。它只由 `repository_map` 工具调用；初始提示和上下文重建不自动执行该扫描。代理通过 `plan_units` 提出路径范围、接口目标、依赖及局部测试。`focus_unit` 检查前置单元检查点并限制编辑范围；实际切换单元触发上下文重建。`checkpoint_unit` 执行语法及声明测试，记录局部证据；上游变更使依赖检查点失效。外部完整验收独立决定最终接受。

此前累计消融的最后一级把上述工具、notebook 单元编辑、版本化证据与上下文重建一起加入。旧结果可用于分析整个组件包，无法将变化归因给自动映射。

根据唯一 `event_*_tool.json` 统计，历史完整方法确实使用了这些工具：

| 仓库 | repository_map | plan_units | focus_unit | checkpoint_unit |
| --- | ---: | ---: | ---: | ---: |
| 时间序列 | 1 | 2 | 3 | 1 |
| 双塔推荐 | 6 | 3 | 5 | 0 |

时间序列的四类调用均发生在首次修复阶段，map 在第 7 次模型调用返回 26 个源端/目标端代码文件。推荐的 map 在调查阶段使用一次、四个修复阶段分别使用 2、1、1、1 次，每次包含 48 个文件。推荐没有执行局部 checkpoint。逐调用来源、阶段和返回字段保存在 `output/repository-map-ablation-20260922/historical_tool_usage.json`；请求中重复携带的历史工具消息没有重复计数。

独立适配器为 `experiments/repository_map_ablation_20260922/map_adapter.py`。消融条件的 `inventory()` 不调用父类扫描，只返回代理已有的计划和活动单元；自动未分配文件清单也一并移除。普通 list/read/search、notebook 读取编辑、plan/focus/checkpoint、语法保护、证据检索、工作集与上下文重建全部保留。工具 schema 仅修改 map 的说明，系统提示仅把自动 map 的使用说明替换为普通公开代码检查说明；独立角色交接生成新提示后仍执行这一替换。共用初译的生成状态在两条件中原样保留，因此本轮不测量初译阶段结构分析的作用。

## 冻结协议

两条件使用同一源程序、共同初译、任务、参考执行材料、输入、评估种子、阈值、模型和完整训练信号。每项最多 80 次模型调用、480,000 输出 token、3,600 秒、四次外部提交，单次最多输出 32,768 token。调查阶段最多六次调用和 64,000 输出 token，第一次修复最多 16 次调用，之后按剩余提交次数分配剩余额度，沿用累计消融原控制器。不新增模型 seed 或 temperature。所有失败调用和费用均计入。

主指标是两个固定仓库的完整外部接受状态。描述指标包括每次外部提交的通过项、未测项、累计调用和 token，以及 map/plan/focus/checkpoint/edit/test 轨迹。时间序列分母仍为 69，推荐仍为 145；这些检查描述同一候选，不作为独立迁移样本。确认种子尚未执行时对应项目保留未测量。

第一轮固定四项运行，调度顺序为时间序列 full/no_automatic_map、推荐 full/no_automatic_map，最多两个并发。建议后续固定追加第 2、3 轮，每轮同样执行两个仓库的完整配对，共追加八项，并汇总全部运行，不根据第一轮效果选择仓库、条件或最优结果。追加轮次已写入冻结协议作为建议，当前没有调度。

## 工作单元规划的后续独立检验

自动映射与工作单元规划需要两个对照才能分别归因。本轮保持不变。后续可加入“保留自动 map，关闭工作单元协调”条件，与新的完整方法配对；同样使用两个仓库、相同初译、完整验收和预算。

关闭规划条件需要作为一个明确组件包移除 `plan_units`、依赖就绪检查、`focus_unit` 的编辑范围约束、`checkpoint_unit` 的依赖传播，以及切换工作单元触发的上下文重建。它们在当前实现中共享单位状态，单独删除 plan 工具会令所有生产编辑无法进行。普通语法检查、run_test、自动 map、notebook、独立调查与交接、版本化证据和容量触发的上下文重建应保留。map 仍返回自动文件/符号/import/cell 信息，去掉无意义的 work-unit 图；公开读取工作集按最近已读且哈希仍匹配的文件保留，继续使用同一字符上限。生成状态在所有条件中相同。

可通过新的 RepositoryTools 子类在无规划时为 production edit 提供全仓库合法编辑范围，重用原事务、只读与语法校验，并重用原 RepositoryAgent 的证据与容量重建。测试需验证无规划时确实能跨文件编辑，源程序仍只读，依赖状态不再限制编辑，容量重建仍可检索此前证据。该条件测量“显式工作单元协调”的整体作用，包括其引起的单元切换整理；不能把全部差异解释成依赖图单一机制。若进一步需要依赖图的独立贡献，可在保留单元范围与焦点的基础上，仅去掉 dependency-ready 门控及上游检查点传播，形成另一个单因素对照。

最完整的后续矩阵是 map 开/关 × 工作单元协调开/关，配合预先固定重复。它可检查 map 的贡献是否依赖显式规划，并解释当前单因素结果；当前四项任务不在运行中改变条件。
