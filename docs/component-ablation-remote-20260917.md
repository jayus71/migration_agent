## 本次中断与修正

补丁记录曾将模型生成的完整策略说明拼入文件名，超过文件系统单个文件名长度限制，导致部分已有 API 回复无法写入或应用补丁。修正后每个文件名组成部分最多 64 个 ASCII 字符，超长部分加入哈希后缀；完整策略、补丁内容仍原样保存在 JSON 中。此行为仅在补测开关启用时生效，四组条件共用相同实现。

旧检查还把 `restored_from_fault` 当作工作目录清理状态；该字段在生成的候选文件中表示修复是否改变故障内容。修正后的检查单独核对临时文件删除证据、文件及符号链接不存在、核心代码恢复情况，并在检查点记录 `cleanup_valid`。正常耗尽预算的失败可以成为有效测量；文件写入等基础设施错误仍判为无效。原始 `passed`、token、尝试次数与旧归档均保持原值。

## 协议核查发现

旧故障实验会回滚所有未通过验收的补丁；论文通用 orchestrator 描述的是根据验证分数是否改善决定回滚。本次补测检验旧故障实验实际使用的回滚机制，沿用各任务已有验证器，不新增全训练步骤配对验证。论文整合时需要明确这一区别。

旧 `EX-06` 路径实际只尝试一次。本轮四组均允许最多四次，完整方法也重新运行。因此，新结果应作为同一轮四组比较呈现。旧汇总中的 `48/50` 不能直接作为这批新控制的完整方法对照。

每个真实 LLM 调用保存提示词、回复和 token 使用量，费用从回复逐次汇总，包含未成功修复的调用。缺少响应、API 错误、模型绑定异常或恢复失败会停止运行，保留待检查记录；正常耗尽预算记为有效失败。没有接受修复时，每个接受修复的成本为 `n/a`。
