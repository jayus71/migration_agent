# 未知故障自主诊断与修复实验

本轮删除已知故障类别、预设根因、修复文件、函数和路由，由工具调用 agent 根据真实执行和公开代码自主归类、定位。按用户确认，原 50 例主比较保留原来的逐故障验收谓词和四轮预算；自然迁移任务另用配对训练验收。证据压缩仅作为我们的方法及消融变量，SWE-agent 与 MatchFix 保留各自原有的历史和流程。旧结果保留，不与新运行拼接。

下文的十例共享工具实验描述已完成的 `formal_v1` 开发比较。后续完整基线比较和原 50 例准备记录见 [autonomous-comparison-progress-20260917.md](autonomous-comparison-progress-20260917.md)。

## 四个条件

| 条件 | 流程 |
| --- | --- |
| `autonomous_layered` | 独立 Verifier 对话自行检查、测试、归类和定位；Fixer 接收完整的实际观测、工具证据和模型诊断后修复。两角色共享总预算。 |
| `swe_style_shared_tools` | 使用同一套工具，以复现、搜索、修改和复测的连续对话完成任务。明确标为 SWE 风格控制。 |
| `matchfix_shared_tools` | 保留冻结上游 MatchFixAgent `66a52a5` 的六种语义分析、测试修复与 verdict 角色及解析器，将 coding agent 后端接入共同的真实工具和预算。 |
| `direct_shared_tools` | 相同初始诊断阶段；每次修复最多两次模型调用、一次可跨文件编辑操作。它是新的直接修复控制。 |

后面三个名字准确标明本轮接入方式。本轮没有声称运行未经适配的官方 SWE-agent，也不把共享工具版本等同于历史 MatchFix 单次文本 wrapper。原版实现、历史结果和接入问题见 [baseline-implementation-audit-20260917.md](baseline-implementation-audit-20260917.md)。

所有条件请求模型 `deepseek-v4-flash`，接口实际返回 `deepseek-flash`；请求温度为 0。该轮未显式配置 thinking，接口启用了推理模式，因此温度参数不能作为确定性保证。每实例最多四次修复轮、40 次模型调用、60,000 输出 token 和 1,200 秒；每次最多 4,096 输出 token，客户端上下文上限为 160,000 字符。初始诊断和每修复轮最多八次调用；MatchFix 的静态分析、工具调用和 verdict 全部计费。Direct 使用其明确限定的更少修复调用。每阶段最后一次可用调用关闭工具，要求保存诊断和当前结果。

首次生产代码修改前保存诊断。正常候选也经历诊断，以检查误报。候选与库在诊断阶段只读，agent 可以创建并运行自己的测试。修复阶段允许相同的候选与库多文件编辑；源程序和运行契约始终只读。重试沿用实际工具历史和验收观测。预算耗尽、接口失败、输出协议失败与数值验收失败分别记录。

## 观测、验收与隔离

通用测量不读取 `fault_id`、`failure_type`、`fix_hints`、`root_cause_ranked` 或预设位置。公开结果从运行报告按字段白名单产生，包含执行状态、loss 差、梯度范数差、逐参数梯度与更新测量，以及逐层输出摘要。执行失败后未完成的测量为 `null`，不以零值表示通过。

配对执行严格同步完整初态，包括参数和缓冲区；参数更新指标只统计参数。训练末尾清除梯度时，从优化器更新前的真实梯度快照采样。除原来的 loss 差 0.02、梯度范数差 0.05、参数更新相对差 0.03 外，增加梯度向量 L2 差 0.05，以拒绝范数相同而方向错误的梯度。公开的逐层与逐参数差异也必须满足对应阈值。

接受要求目标训练真实产生与当前模型和返回 loss 对应的 MindSpore 求导记录，且源程序和契约哈希未变。仅导入适配层、运行无关目标算子、回退原生 PyTorch 均不构成成功。初次通过后，在种子加 1000、加 2000 的两个输入上复验；三次均通过才接受。额外种子与严格梯度检查使本轮验收不同于历史单步结果。

模型只能调用列表、搜索、读取、精确编辑和测试五类工具。自建测试以 Landlock 限制文件访问，seccomp 禁止出站连接和跨进程读取；子进程不继承 API 密钥。评估代码、其他任务、历史结果与宿主用户目录不在可读范围。真实 MindSpore 前向和求导、路径越界、只读文件和网络限制已有运行测试。

每次 API 请求、回复、实际返回模型名、usage、工具参数和真实输出逐次落盘。缺失 usage 标为未知，不捏造成本。接口失败已经产生的成本仍计入总账。各条件的代码初态、每次修复前后及最终版本均保存；正式执行使用独立代码快照和逐文件哈希。

## 结果与评分

运行目录为 `experiments/autonomous_verifier_20260917/`。`development_v1` 保存不调用 LLM 的基础设施检查，`formal_v1` 保存冻结输入、预检、代码快照、条件轨迹和汇总。`formal_v1` 的 40 个条件已全部结束，无基础设施错误。四个方法均为 5/10 接受，通过的五例全部初始即健康；初始失败的五例均未修复。此轮没有得到方法领先证据。

复核发现客户端上下文上限使多例提前退出；部分请求的 4,096 输出 token 全部用于推理，最终正文为空且 `finish_reason=length`。这些失败和成本保留在结果中。下一轮显式配置推理模式、扩大单次输出额度，并解除过小的客户端上下文门槛；冻结旧快照保持可追溯。

归类、机制解释、位置和修复接受分别审核。自然案例的私有评估标准见 [autonomous-diagnosis-assessment-20260917.md](autonomous-diagnosis-assessment-20260917.md)，没有复制进 agent 的可见目录。尚缺独立真值的精确根因保留未审定状态，不将人工推测算成确定的定位标签。
