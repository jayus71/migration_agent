## 参考摘要的篇幅与逻辑

| 论文 | 近似英文词数 | 摘要的主要论证顺序 |

| CGDM | 195 | 域适应任务 → 分类器输出相似仍可能分错 → 梯度提供语义监督 → 梯度与伪标签的构造 → 实验结论 |
| DAPM | 214 | 现有方法的不确定性估计不足 → 概率建模 → 推断、采样和样本选择如何衔接 → 校准与性能结果 |

计数采用仓库原有的英文词组规则 `[A-Za-z]+(?:'[A-Za-z]+)?`，连字符连接的词分开计数，数字不单独计词。Zhekai Du 的计数来自已核对的摘要选段；另两篇去除摘要标签，ExeCoder 也去除末尾代码链接。因此这些数值是统一规则下的近似词数，不是投稿系统的字数统计。

六篇 Zhekai Du 论文的摘要为 191–230 词，平均约 206 词。篇幅较长的部分主要用于说明问题、设计依据和方法之间的联系。CGDM 与本文最接近的论证关系是：观察到的输出相似，仍不足以保证真正关心的行为正确；需要给出与目标行为对应的额外信号。DAMP 则说明怎样通过组件间的信息交互解释方法，而不是只列组件名称。LoCA 的理论部分较多，本文应借鉴其设计依据的组织方式，不引入本研究没有的理论证明。

MatchFixAgent 在方法介绍中直接说明多 agent 如何分解验证任务。这可以帮助本文突出 agent，但本文需要写清自己的协作依据：训练顺序中的诊断如何决定修复动作，以及新的验证结果如何进入下一轮修复。

Zhekai Du 论文的 PDF、版本及摘要位置见 [来源记录](../literature/zhekai-du/STYLE-EVIDENCE.md)、[选段索引](../literature/zhekai-du/prose_selection.json) 和 [已有计数](../literature/zhekai-du/prose_metrics.json)。另两篇直接核对了 [ExeCoder 的 ACL 摘要](https://aclanthology.org/2025.emnlp-main.362/) 与 [MatchFixAgent 的 arXiv 摘要](https://arxiv.org/abs/2509.16187)。

## 本文摘要的调整

上一版按空格计数为 149 词。当前版为 221 词，按上表英文词组规则约为 220 词。扩充内容放在诊断依据和 agent 协作上，数字结果仍集中在一句。

1. 先说明执行成功仍可能出现梯度或参数更新错误。
2. 说明前向检查的覆盖不足，以及整体通过或失败反馈缺少修复指向。
3. 以训练阶段的依赖关系解释为什么最早的分歧有诊断价值。
4. 明确 MARS 是多 agent 修复系统，编排器协调翻译、验证和修复三个 agent。
5. 说明初始翻译、按序验证、诊断指导修改、再次验证之间的关系。
6. 保留原50实例、四次尝试、84%首轮接受和约29倍成本优势，并保留原跨框架结尾。

摘要正文以 [LaTeX 源稿](../conference_101719.tex) 为准。编排器与 agent 的关系沿用本地实现 `ascend-torch4ms/autofix/orchestrator.py`，不将编排器算作第四个 agent，也不声称三个 agent 都由 LLM 实现。

## 当前标题与缩写

**MARS: A Multi-Agent Repair System for Training Code Migration via Layered Diagnosis**

MARS 来自标题中的 **M**ulti-**A**gent **R**epair **S**ystem。`for Training Code Migration` 指定应用任务，`via Layered Diagnosis` 说明核心机制。正文、公式中的方法下标、图注、主表和在用图表的名称已同步。原实验标识保持不变。

摘要将 `first, then, finally` 串联的检查顺序改为直接表述：

> The verifier compares execution status, forward values, gradients, and parameter updates between source and target programs in training order.

这样仍表达训练顺序，结果中的 `first attempt` 保留其指标含义。

## 引言结构方案（已按审核意见实施）

原引言在任务背景、相关工作分类、故障现象、训练顺序和系统介绍之间切换。图1的检出证据与“诊断如何指导 agent 修复”的联系展开不足，多 agent 协作在靠后位置才出现。用户确认以下方案后，已将五个主体段落收为三个，贡献引导句接在第三段末尾，并保留三项贡献。

### 第一段：跨框架训练代码给修复 agent 带来的具体难点

从 LLM agent 翻译和迭代修复训练程序这一任务开始，将当前背景段和故障段合并。说明可执行性之外，还需保留梯度、参数更新等决定学习行为的计算。以少数代表工作说明现有 agent 能够编辑代码、使用执行反馈，引出本文关注的缺口：反馈需要揭示训练行为的分歧，并为 agent 的修复动作提供依据。

本段应让读者明确研究对象和问题。现有三类工作的详细分类留在 Related Work，不在引言中逐类列举。

### 第二段：从观测到的故障推导诊断依据

以图1解释前向检查可能遗漏或延迟发现训练错误，并区分每个运行在第1步检出与平均损失曲线在第31/18步越过阈值。随后说明执行、前向计算、梯度和参数更新的依赖关系。补充信号扩大了可检出的故障范围；按训练顺序组织这些信号，使最早的分歧成为选择修复位置的依据。

本段应把“检测到错误”推进到“获得可指导修复的诊断”。图1支持诊断信号的必要性；阶段指引对修复的作用由后文消融分析，不把图1写成多 agent 协作收益的直接证据。原25类故障的构造和分类细节在实验设置中展开。

### 第三段：分层诊断如何组织多 agent 迁移修复

顺着第二段的诊断依据引入 MARS。用连贯的信息流说明三个 agent 的作用：翻译 agent 给出候选程序，验证 agent 产生分层诊断，修复 agent 根据诊断修改代码，编排器组织复验与后续修复。段落重点是诊断如何决定修复动作，以及修改后的验证结果如何驱动下一轮协作。

段尾简述 MindSpore 和 JAX 的验证范围及主要修复、成本表现。执行适配器的接口和仓库实现细节放在 Method。本段后保留三项简明贡献，分别对应分层训练诊断、诊断驱动的多 agent 修复，以及跨框架实验验证。
