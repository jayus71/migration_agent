This standalone preview follows the September 25 request for a layered diagnosis, the resulting code repair, and cumulative token trajectories. It is not yet included in the manuscript. Generate the PDF, PNG, editable-text SVG and numerical/layout audit with `.venv/bin/python figures/make_tanh_repair_case.py`. Four aligned diagnosis cards span the top row. The two code blocks sit below on the left, and the cost plot sits below on the right; the lower panel titles share a baseline. A common point grid controls all placement. The canvas is 5.5 × 3.528 inches; all text uses Times New Roman, including 8.5-point code. The four inserted code lines have a green background and plus signs.

The evidence is the [audited saved translation](../../docs/repair-case-study-20260925.md). The two baselines have identical unchanged code at the repair site, so they share one block showing the existing ReLU registration. LaDiM inserts the highlighted Tanh registration immediately before it. This is an insertion, not replacement of ReLU. The plotted cumulative values contain every saved call: 24 for LaDiM and 40 for each baseline, including failed investigation and the final report. Crosses mark unrepaired terminal candidates. Call 23 is the public acceptance test; the full cost includes call 24 and the saved external evaluation confirms all three seeds.

The diagnosis row uses initial observations and the executed tool event at call 17. Forward/loss checks pass, while only the parameters before Tanh lose their gradients; downstream parameter gradients match. The update error is the relative L2 difference, 0.771. The focused test compares the sum of absolute input gradients: dispatched Tanh gives zero and native MindSpore Tanh gives 4.894132. The missing high-level registration routes execution through copied PyTorch tensors and breaks the target differentiation graph. These cards summarize the observed diagnostic reasoning; they do not claim four separate detection times or baseline inability to recognize the same mechanism.
