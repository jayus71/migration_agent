\begin{abstract}
Migrating deep learning code across frameworks is a practical requirement for reusing training programs in new software and hardware environments. Framework differences can change how a translated program computes gradients and updates its parameters without causing runtime errors. To address this problem, we propose LaDiM, a multi-agent framework that uses dependencies between training computations to guide diagnosis and repair. Starting from an initial translation, the Verifier Agent investigates where the target program diverges from the source and passes supporting code observations and test results to a separate Repair Agent. The Orchestrator returns measurements after each submitted change to guide further repair. Repository context management supports repair across files by tracking dependencies and retaining relevant evidence. Experiments on MindSpore and JAX, together with Java-to-Python migration, demonstrate LaDiM's effectiveness across frameworks and programming languages. Compared with MatchFixAgent, LaDiM matches full acceptance on 50 PyTorch-to-MindSpore tasks and achieves higher acceptance on Java-to-Python migration, using 57.4\% and 24.2\% fewer total tokens, respectively.
\end{abstract}

\section{Introduction}

Migrating deep learning code allows existing models and training programs to run in new software and hardware environments. Differences in operator semantics, numerical precision, and random number handling can change the computations performed after migration. Automatic differentiation and optimizer interfaces introduce further differences in how a model learns~\citep{paszke2019pytorch,mindspore2020whitepaper}. Large language models (LLMs) reduce the manual effort involved in code translation~\citep{he-etal-2025-execoder,macedo2024intertrans}, while automated tests and interactive repair help assess and correct translated behavior~\citep{roziere2021unittests,yang2024sweagent,ibrahimzada2025matchfixagent}. Training programs require these capabilities to preserve the computations that determine each parameter update.

A translated program can produce a loss close to that of the source while computing incorrect gradients. An optimizer error can also alter the parameter update without changing the current loss or gradients. We use semantic drift to describe these changes in training behavior caused by migration. Training computations have dependencies that help investigate such errors. A forward error may change gradients and updates, while an incorrect update may affect later forward computations. Locating the cause requires examining how the translated code produces the observed differences. This investigation also affects migration cost. Figure~\ref{fig:migration-motivation} compares complete token use on common migration tasks, where LaDiM achieves full acceptance with less than half the tokens used by MatchFixAgent.\par}

We introduce LaDiM (Layered Diagnosis for Multi-Agent Code Migration), which uses dependencies between training computations to guide investigation of an initial translation. The Verifier Agent inspects code and runs tests to establish where source and target behavior diverge. For example, matching forward values with missing gradients directs attention to parameter registration and the differentiation path. The agent records the code and measurements supporting its hypotheses and passes this evidence to a separate Repair Agent. After a change is submitted, the Orchestrator runs the acceptance checks and returns new measurements to guide subsequent attempts. This feedback connects each correction to the behavior it changes and exposes the next computation to investigate.

For repositories, migration must preserve shared implementations across multiple entry points. A change that corrects one caller can alter the behavior of another, and investigation may need evidence collected earlier in a different file. LaDiM tracks dependencies between work units and invalidates checks affected by changes. It retains observations and hypotheses in a retrievable archive and rebuilds the working context when the investigation moves between units. Together, these operations support repair across files while preserving the relationship between code changes and their measured effects.

We evaluate migration acceptance and model use from common initial translations under a shared protocol. LaDiM's token savings cover both repair of faulty translations and confirmation of candidates that already pass the checks. On a time series repository, all three evaluated agents complete migration, with LaDiM using fewer tokens and repair calls. On a recommendation repository, LaDiM achieves the highest behavioral coverage and passes all ten original tests. Training signal and component ablations examine how observations and agent organization affect repair, while JAX and Java-to-Python experiments establish effectiveness across frameworks and languages. Our contributions are as follows.

\begin{itemize}
  \item We formulate training-code migration around execution, forward values, gradients, and parameter updates, using their dependencies to investigate semantic faults.
  \item We develop LaDiM with independent investigation, evidence handoff, and verification after repair, together with dependency and context management for repositories.
  \item We evaluate migration across frameworks and languages, comparing acceptance and total token use and analyzing repair behavior, training signals, and agent components.
\end{itemize}

\section{Related Work}

\paragraph{Code Translation and Framework Migration.}
Neural translation methods learn code mappings from multilingual corpora and use automated tests or compiler representations to improve translations~\citep{roziere2020transcoder,roziere2021unittests,szafraniec2023compiler}. ExeCoder encodes functional semantics, syntax structure, and variable dependencies~\citep{he-etal-2025-execoder}, while InterTrans explores intermediate translation paths~\citep{macedo2024intertrans}. Framework migration tools such as MindConverter supply mappings between programming interfaces~\citep{mindspore2023mindconverter}. RepoTransAgent uses repository context, test failures, and reflection to refine translated code~\citep{guan2025repotransagent}. LaDiM investigates how a translated training program computes and updates its state. At repository scale, it coordinates changes to shared interfaces and checks their effect across declared entry points.

\paragraph{Differential Testing and Deep Learning Verification.}
Differential testing exposes compiler and program faults through disagreement between related executions~\citep{yang2011csmith,le2014emi}. DeepXplore and DeepGauge investigate behavioral differences and test coverage in deep learning systems~\citep{pei2017deepxplore,ma2018deepgauge}. More directly related to framework migration, TensorScope tests corresponding APIs across frameworks to identify inconsistent behavior~\citep{deng2023tensorscope}. NablaFuzz compares execution scenarios to test automatic differentiation, including first-order and higher-order gradients~\citep{yang2023nablafuzz}. LaDiM uses training differences as evidence for code repair. Its Verifier Agent relates the measured forward values, gradients, and parameter updates to the implementation, develops hypotheses about their origin, and supplies evidence that the Repair Agent can test when selecting a change.

\paragraph{Automated Program Repair and LLM Agents.}
Automated program repair uses tests or semantic constraints to guide patch generation~\citep{nguyen2013semfix}, and pretrained language models generate patches from code and failure evidence~\citep{xia2023aprplm}. Interactive agents combine repository navigation, editing, and execution~\citep{yang2024sweagent,shinn2023reflexion,chen2023selfdebugging,wang2024codeact}. Multi-agent systems distribute development activities among specialized roles~\citep{qian2023chatdev,hong2023metagpt,wu2023autogen,chen2023agentverse}. MatchFixAgent takes a source program and an existing translation and uses several semantic analyses to guide test generation and repair~\citep{ibrahimzada2025matchfixagent}. LaDiM includes initial translation and organizes diagnosis around dependencies in training computations. The independent investigation and its supporting observations pass to a separate Repair Agent, which uses measurements after each submission to revise its hypotheses. The comparison evaluates both methods from the same initial translation and includes translation costs.

\section{Conclusion}

We introduced LaDiM, a multi-agent framework for migrating deep learning code while preserving training behavior. LaDiM uses dependencies between training computations to guide diagnosis and passes the resulting evidence to a separate Repair Agent. Verification after each submission guides subsequent changes, and dependency tracking with evidence retrieval supports repair across files. This design detects and repairs semantic errors that remain hidden when evaluation checks only execution or loss. Experiments across frameworks and programming languages demonstrate LaDiM's effectiveness in preserving training behavior and its efficiency in diagnosis and repair.
